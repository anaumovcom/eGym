# Position mode · dual Lichuan A6 (commissioning)

The new position exercise controller is **SIM:// only**. It does **not** energize physical drives. The existing `ModbusDriveAdapter` remains blocked (`E-CTRL-UNAVAILABLE`); automatic workout runtime is not yet wired to this simulation-only controller. The Position-mode exercise editor is reached through Modbus → Position · упражнение, or from the setup screen for an exercise. Its per-exercise settings are stored in this browser only, not in the workout database.

## Simulation

Connect two distinct Modbus IDs using `SIM://` (300 ms timeout). Startup atomically captures both encoder counters as software zero. Set the physical upward sign per side (+1 or −1) before connecting. `GET /api/modbus/positions` and the monitor expose relative millimetres. Zero again only when no exercise/raise is running.

The Position tab captures lower/upper or fixed points from **both Modbus encoders** (average, with ≤3 mm skew), keyed by exercise and bound to this startup's software-zero generation. This calibration is held in backend memory, not in the ordinary exercise-calibration database; a reconnect, restart or zero capture invalidates it. Capture lower AND upper for a lower-boundary exercise, or fixed for a fixed-position exercise. Only use these points as goals. The legacy exercise-setup and exercise-session screens use a separate hardware controller's feedback; when Modbus is connected they do not record its values or start a standard workout. Do not mistake an exercise launched from the Position tab for a tracked/saved workout.

"Weightless bar" in the Position tab uses the same segment 0, target +2000 mm, POS_LOAD and Servo-ON, but uses a **separately entered, low torque limit** on PA_05E and PA_05F. An operator must explicitly provide an independently measured threshold at which the actual load starts to move unassisted, and the configured limit must be strictly below that threshold. There is deliberately no default threshold. Even this comparison **cannot guarantee** the bar stays still (friction, gear ratio, load and torque units vary); the operation remains SIM-only. In this mode a large difference from +2000 mm is expected and is not treated as a fault. Hold changes the goal to the present bar height at limit 300 without Servo-OFF; capture points are allowed in simulated weightless/hold but re-zeroing is prohibited. Stopping the simulation raises to +2000 mm only if that remains inside the active software limits.

Set target type `lower_boundary` or `fixed_position`, goal in mm, torque limit (100/200/300 ≈ 10/20/30% rated), speed (rpm) and software min/max. Starting the exercise checks both encoders, alarm, PA_002=0, PA_090=1, bounds and ≤3 mm skew. For each side it writes both limits (PA_05E/PA_05F), the signed 32-bit absolute target (software zero + upward sign × round(mm × 312.5)) to position segment 0 (PA_168/169), speed to PA_190, selects PA_091=0, asserts Servo-ON, and pulses POS_LOAD. No torque command is written. Unchanged targets are not reloaded; limit-only changes update PA_05E and PA_05F. STOP changes the goal to +2000 mm, limit 300 and speed 30 rpm, **not Servo-OFF**. The old software-stop API refuses to zero torque or disable the servos.

The monitor reports both positions, skew, status, alarm, position error, command/actual speed and torque; alarms, >3 mm skew, bounds violations and loss of encoder communication fault the simulation. Sustained actual torque near the limit with <0.1 mm displacement for 2 s also faults. >10 mm positional deviation warns (large deviations are expected during a normal move). On simulated faults it attempts to hold the current counts, without releasing servo enable. This is **not** a physical safety function. Browser polling does not constitute a hardware watchdog.

## Blockers before any real load-bearing test

- Independently verify A6 register addresses, data types, position command mode (absolute vs incremental), DI0 mapping, POS_LOAD DI mapping and timing/edge behaviour, enabled/status feedback, torque-limit direction symmetry, error/status registers and persistence/restart semantics **against the exact driver firmware**.
- Implement and test drive-side watchdog for Modbus loss, mechanical brake, limit switches and hardwired hardware E-STOP/STO. Never interpret a Modbus acknowledgement as proof that the bar has stopped or is supported.
- Implement coordinated left/right fault handling and real-time skew supervision outside the browser; sequential RTU polling cannot guarantee a 300 ms reaction time on two drives.
- Calibrate speed and torque under no load with an independently secured bar; 30 rpm is only a simulation commissioning placeholder.
- Integrate validated exercise settings into the persisted workout model and production exercise lifecycle, then review a separate safety case before unlocking the real adapter. Until then STOP on a real drive returns `E-CTRL-UNAVAILABLE`: use the **hardware E-STOP** for emergencies.
