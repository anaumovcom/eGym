# Автообрезка фотографий прогресса на CPU

Все новые загрузки через `POST /api/photo-progress` обрабатываются локально на сервере.
Существующие фотографии автоматически не изменяются.

## Серийная съёмка

Кнопка «Снять серию» в модалке снимает **три кадра всего**: спереди → сбоку → сзади.
Перед каждым кадром запускается полный выбранный таймер (3, 5 или 10 секунд;
«Без» — без задержки). Подсказка ракурса и номер кадра показываются поверх живого видео.
Во время серии выбор ракурса, таймера и сохранение заблокированы.
«Отменить серию» останавливает следующие кадры, сохраняя уже сделанные черновики.
Закрытие окна также останавливает серию. Ошибка захвата кадра прерывает серию.
Новая серия переснимает все три ракурса; предыдущий черновик ракурса заменяется
только при успешном получении нового кадра. На сервер снимки отправляются после
нажатия «Сохранить» и проходят описанную ниже CPU-обработку.

## Результат

- YOLOX-S находит человека целиком, а не только лицо; при нескольких людях выбирается самая большая фигура после NMS.
- К фигуре добавляется запас 8% с каждой стороны, затем рамка расширяется до вертикального **3:4**.
- Человек не растягивается. Формат может потребовать больше свободного места по бокам.
- Если человек у края, рамка смещается внутрь исходника. Когда необходимая рамка больше исходника, недостающая область заполняется чёрным, а не обрезает фигуру.
- Итог — JPEG до **900×1200**, миниатюра до **240×320**. Небольшие исходники не увеличиваются.
- EXIF-ориентация применяется до поиска человека; GPS и прочий EXIF не сохраняются.
- Сохраняется обработанный кадр, не широкий оригинал. Размеры, MIME и размер файла в БД соответствуют обработанному JPEG.
- Если человека нет, API возвращает 400 с просьбой переснять. При отсутствии/ошибке модели — 503. Необработанный исходник в этих случаях не сохраняется.
- Это кадрирование, не удаление/замена фона: окружение внутри рамки остаётся естественным.

## Установка

Зависимости включены в `backend/pyproject.toml`: **onnxruntime**, не `onnxruntime-gpu`, и NumPy.
После установки зависимостей один раз запустить из корня проекта:

```sh
.venv/bin/python backend/scripts/install_photo_model.py
```

Модель (~36 МБ) устанавливается в `backend/models/object_detection_yolox_2022nov.onnx`.
Путь можно изменить переменной `PHOTO_PERSON_MODEL_PATH`. Каталог моделей не включается в Git и не публикуется через `/media`.
Установщик закрепляет ревизию и проверяет SHA-256; без совпадения контрольной суммы файл не устанавливается.
Для офлайн-развёртывания этот файл следует скопировать вместе с приложением.
При съёмке/сохранении сетевых запросов к поставщику модели нет; фото никуда не отправляются.

## CPU и безопасность исполнения

ONNX Runtime запускается с единственным провайдером **CPUExecutionProvider**.
CUDA, GPU и внешние сервисы не используются. До двух вычислительных потоков,
последовательное исполнение, отключённое активное ожидание потоков и блокировка
параллельных инференсов ограничивают конкуренцию с другими задачами backend.
Сессия загружается лениво и повторно используется между снимками.

## Проверки

`backend/app/tests/test_photo_crop.py` проверяет геометрию и поля, края кадра,
EXIF, CPU-провайдер, RGB/letterbox-подготовку, подавление дубликатов и выбор
человека, загрузку/миниатюру/метаданные и отсутствие сохранения при ошибках.
Тесты работают с подменой вывода детектора и не требуют скачивания весов.
