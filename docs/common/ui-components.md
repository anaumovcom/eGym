# Реестр универсальных UI-компонентов Forma

## Назначение документа

Этот документ фиксирует компоненты, которые должны использоваться повторно на разных экранах Forma.

Цель:

* не дублировать одну и ту же логику в документации экранов;
* сохранить единые состояния, цвета и поведение;
* упростить проектирование интерфейса для 4K-монитора и сенсорного управления;
* явно определить, какие элементы являются компонентами, а какие — частью конкретного экрана.

---

# Главное правило

Если один и тот же блок встречается на двух и более экранах, он должен рассматриваться как переиспользуемый компонент.

Экранные документы описывают:

```text
где компонент стоит;
какой режим используется;
какие данные передаются;
какие действия доступны.
```

Этот документ описывает:

```text
общую структуру компонента;
режимы;
состояния;
переиспользование;
единые правила поведения.
```

---

| `PrimaryActionBar` | Нижние/главные действия | Тренировка, упражнение, итог, профиль |

# 1. `TopSystemBar`

## Назначение

Единая верхняя панель приложения.

Канонический вид:

```text
Forma  [Алексей]  [Тренажёр готов]  [Левый привод: подключён]  [Правый привод: подключён]  [Безопасность включена]  [СТОП]
```

## Режимы

| Режим | Где используется | Особенность |
| ----- | ---------------- | ----------- |
| `default` | Основные экраны | Полный набор статусов |
| `noUser` | Выбор пользователя | Без имени пользователя |
| `compactLive` | Выполнение упражнения | Компактнее, `СТОП` визуально сильнее |
| `service` | Настройки / сервисный режим | Показывает инженерный режим и блокировки |

## Состав

```ts
type TopSystemBarProps = {
  appName: 'Forma';
  userName?: string;
  machineStatus: 'ready' | 'warning' | 'blocked' | 'service';
  leftDriveStatus: 'connected' | 'disconnected' | 'warning' | 'error';
  rightDriveStatus: 'connected' | 'disconnected' | 'warning' | 'error';
  safetyStatus: 'enabled' | 'disabled' | 'emergency_stop';
  mode: 'default' | 'noUser' | 'compactLive' | 'service';
};
```

# 2. `LeftNavigationMenu`

## Назначение

Единое левое меню основных экранов.

```text
Главная
Быстрый старт
Сегодня
Календарь
Конструктор
Программы
Каталог
Прогресс
Усталость
Профиль
Настройки
```

## Правила

1. Активный пункт подсвечивается золотым акцентом.
2. Меню не скроллится вместе с контентом.
3. На промежуточных экранах меню можно оставить, если это не мешает безопасности.
4. На live-экране выполнения упражнения меню можно скрыть или сделать компактным.

# 3. `EmergencyStopButton`

## Назначение

Кнопка `СТОП` — отдельный компонент, а не обычная кнопка.

## Правила

1. Всегда видна.
2. Красная.
3. Не должна выглядеть как вторичное действие.
4. Не размещается рядом с обычными кнопками так, чтобы её можно было случайно нажать.
5. При нажатии открывает `EmergencyStopOverlay` и блокирует движение.

## Состояния

```text
Обычное состояние
Наведение / фокус
Нажата
Аварийная остановка активна
Разблокировка требуется
```

# 4. `MuscleMap`

## Назначение

`MuscleMap` — универсальная карта тела для отображения:

* текущей усталости;
* нагрузки за период;
* мышц конкретного упражнения;
* мышц тренировки;
* баланса программы.

Это главный переиспользуемый компонент для мышечной аналитики.

---

## Где используется

| Экран | Режим |
| ----- | ----- |
| Главная | `fatigueCurrent` |
| Усталость / карта мышц | `fatigueCurrent`, `fatigueAfterWorkout`, `load7Days`, `load30Days` |
| Прогресс → Мышцы | `periodLoad` |
| Карточка упражнения → Мышцы | `exerciseMuscles` |
| Сегодняшняя тренировка | `workoutLoad` |
| Итог тренировки | `workoutSummaryLoad` |
| Конструктор тренировок | `programBalance` |
| Библиотека программ | `programCompatibility` |

---

## Режимы

```ts
type MuscleMapMode =
  | 'fatigueCurrent'
  | 'fatigueAfterWorkout'
  | 'periodLoad'
  | 'exerciseMuscles'
  | 'workoutLoad'
  | 'workoutSummaryLoad'
  | 'programBalance'
  | 'programCompatibility';
```

---

## Варианты компонента

| Компонент | Назначение |
| --------- | ---------- |
| `MuscleMapCompact` | Маленькая карта в карточках и сводках |
| `MuscleMapDetailed` | Большая карта на полном экране усталости |
| `MuscleMapInteractive` | Карта с кликом по мышце |
| `MuscleMapLegend` | Легенда цветов |
| `MuscleDetailsPanel` | Панель выбранной мышцы |

---

## Данные

```ts
type MuscleMapProps = {
  mode: MuscleMapMode;
  view: 'front' | 'back' | 'both';
  variant: 'compact' | 'detailed' | 'interactive';
  selectedMuscleId?: string;
  muscles: MuscleMapItem[];
  showLegend?: boolean;
  onMuscleClick?: (muscleId: string) => void;
};

type MuscleMapItem = {
  id: string;
  name: string;
  status:
    | 'ready'
    | 'light_fatigue'
    | 'medium_fatigue'
    | 'high_fatigue'
    | 'critical_fatigue'
    | 'no_data'
    | 'low_load'
    | 'medium_load'
    | 'high_load'
    | 'very_high_load'
    | 'primary'
    | 'secondary'
    | 'stabilizer';

  fatigueScore?: number;

  readinessPercent?: number;

  recoveryHalfLifeHours?: number;

  lastFatigueCalculatedAt?: string;

  estimatedRecoveryHours?: number;

  value?: number;
  explanation?: string;
};
```

Для режимов усталости `fatigueScore` отображается как число из 100:

```text
Грудь — 72 из 100
Спина — 7 из 100
Грудь — 150 из 100
```

`100` — граница очень высокой усталости, но значение может быть выше `100`. Расчёт снижения усталости по фактическому времени описан в:

```text
docs/common/muscle-fatigue-model.md
```

---

## Поведение при клике по мышце

Если карта интерактивная:

```text
Клик по мышце
→ открыть MuscleDetailsPanel
```

`MuscleDetailsPanel` должен показывать:

```text
Название мышцы
Статус
Усталость: N из 100
Почему такой статус
Последняя нагрузка
Примерное восстановление
Рекомендованные действия
Связанные упражнения
```

Если карта компактная, клик может вести на полный экран `Усталость`.

# 5. `ExercisePreviewCard`

## Назначение

Единая карточка упражнения для списков и сеток.

## Варианты

| Вариант | Где используется | Состав |
| ------- | ---------------- | ------ |
| `catalogTile` | Каталог | Видео-превью, название, мышцы, метки, действия |

## Базовые действия

```text

[Подробнее]

[Добавить]
[Заменить]

[В чёрный список]
```

Поведение зависит от экрана и описывается в экранном документе.

# 8. `LoadSettingsControl`

## Назначение

Единый компонент настройки нагрузки и объёма.

## Используется на экранах

* Быстрый старт.
* Настройка упражнения.
* Конструктор тренировок.
* Правая панель выбранного упражнения.

## Состав

```text
Вес / нагрузка
Подходы
Повторы или время
Отдых
Режим нагрузки
Темп
```

Для упражнений без тренажёра вес заменяется на:

```text
Собственный вес
Без отягощения
```

Для упражнений на время повторы заменяются на таймер.

# 10. `WarningBanner` и `BlockingAlert`

## `WarningBanner`

Используется, если пользователь может продолжить действие:

```text
Грудь имеет среднюю усталость.
Можно тренироваться, но лучше снизить нагрузку.
```

Действия:

```text
[Понятно]
[Изменить]
[Подробнее]
```

## `BlockingAlert`

Используется, если действие запрещено:

```text
Запуск заблокирован

Правый привод не подключён.
```

Действия:

```text
[Открыть диагностику]
[Повторить проверку]
[Назад]
```

# 11. `PrimaryActionBar`

## Назначение

Нижняя или главная зона действий экрана.

## Правила

1. Основная кнопка одна.
2. Вторичные действия не должны конкурировать с основной кнопкой.
3. Опасные действия отделяются визуально.
4. Для сенсорного управления кнопки крупные и с большим интервалом.

# Компоненты и модальные окна

Если компонент открывает модальное окно, панель или всплывающее сообщение, его поведение описывается в документе:

```text
docs/common/modals-panels-overlays.md
```

---

# Ключевые требования

1. Не дублировать разные версии одного компонента на разных экранах.
2. Компоненты должны поддерживать 4K и сенсорное управление.
3. Цветовая логика должна быть одинаковой на всех экранах.
4. `MuscleMap` должен использовать общие режимы и статусы.
5. `ExercisePreviewCard` должен иметь единые варианты, а не разные несвязанные карточки.
6. Любое опасное действие должно использовать `ConfirmDialog`.
7. Любая блокировка запуска должна использовать `BlockingAlert`.
8. Короткие успешные сообщения должны использовать `ToastNotification`.
