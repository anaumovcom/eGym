# Модель усталости мышц Forma

## Назначение документа

Этот документ описывает, как Forma должна считать усталость мышц, как она повышается после упражнений и как снижается со временем.

Главное требование:

```text
Усталость должна уменьшаться по фактическому прошедшему времени,
даже если сервер, приложение или тренажёр были выключены.
```

---

# Основной параметр

Для каждой мышцы хранится числовой показатель:

```text
fatigueScore
```

Отображение в интерфейсе:

```text
Усталость: 7 из 100
Усталость: 48 из 100
Усталость: 150 из 100
```

`100` — условная граница очень высокой усталости.  
Значение может быть выше `100`, если мышца была сильно перегружена.

---

# Интерпретация значения

| `fatigueScore` | Статус | Значение |
| -------------- | ------ | -------- |
| `0–9` | готова | Можно тренировать без ограничений. |
| `10–29` | лёгкая усталость | Можно тренировать умеренно. |
| `30–59` | средняя усталость | Лучше снизить объём или вес. |
| `60–99` | высокая усталость | Лучше не нагружать тяжело. |
| `100+` | критическая / перегруз | Не рекомендуется нагружать эту мышцу. |

---

# Связь с готовностью

Для простого UI можно показывать готовность как обратную величину:

```text
readinessPercent = clamp(100 - fatigueScore, 0, 100)
```

Примеры:

| Усталость | Готовность |
| --------- | ---------- |
| `7 / 100` | `93%` |
| `48 / 100` | `52%` |
| `100 / 100` | `0%` |
| `150 / 100` | `0%` |

Важно: если усталость выше `100`, готовность не становится отрицательной. Она остаётся `0%`.

---

# Как усталость растёт

После каждого выполненного упражнения Forma добавляет усталость задействованным мышцам.

Пример:

```text
Жим с пола со штангой

Грудь: +32
Трицепс: +18
Передняя дельта: +10
Кор: +4
```

Усталость зависит от:

* роли мышцы в упражнении;
* количества подходов;
* повторов;
* веса;
* времени под нагрузкой;
* интенсивности;
* амплитуды;
* темпа;
* субъективной сложности;
* дискомфорта;
* выполнения сверх плана;
* неполного выполнения.

---

# Коэффициент роли мышцы

| Роль мышцы | Коэффициент |
| ---------- | ----------- |
| Основная | `1.0` |
| Дополнительная | `0.6` |
| Вспомогательная | `0.35` |
| Стабилизатор | `0.2` |

Пример:

```text
Если упражнение даёт базовую усталость 30:

Грудь как основная мышца: 30 × 1.0 = +30
Трицепс как дополнительная: 30 × 0.6 = +18
Кор как стабилизатор: 30 × 0.2 = +6
```

---

# Базовая формула прироста

Упрощённая логика:

```text
fatigueDelta = baseLoad
  × muscleRoleFactor
  × intensityFactor
  × volumeFactor
  × qualityFactor
  × subjectiveFactor
```

Где:

| Параметр | Что учитывает |
| -------- | ------------- |
| `baseLoad` | тип упражнения и базовую нагрузку |
| `muscleRoleFactor` | роль мышцы в упражнении |
| `intensityFactor` | вес, сложность, процент от обычной нагрузки |
| `volumeFactor` | подходы, повторы, время под нагрузкой |
| `qualityFactor` | амплитуда и темп |
| `subjectiveFactor` | легко / нормально / тяжело, дискомфорт |

---

# Пример прироста после подходов

```text
Тяга сверху
3 подхода × 10 повторов
45 кг
Ощущение: нормально
Амплитуда: 92%

Спина: +28
Бицепс: +17
Предплечья: +9
Кор: +4
```

Если пользователь сделал больше плана:

```text
3 подхода × 12 повторов вместо 10

Спина: +34
Бицепс: +20
Предплечья: +11
```

Если упражнение завершено частично:

```text
2 подхода из 3

Спина: +18
Бицепс: +11
```

# Как усталость снижается со временем

Усталость должна снижаться по фактической разнице времени.

Для этого у каждой мышцы хранится момент последнего пересчёта:

```text
lastFatigueCalculatedAt
```

При каждом открытии приложения, экрана или запросе рекомендаций нужно пересчитать усталость:

```text
elapsedHours = nowUtc - lastFatigueCalculatedAt
currentFatigue = previousFatigue × recoveryDecay(elapsedHours)
```

---

# Рекомендуемая модель восстановления

Используем экспоненциальное снижение через период полураспада:

```text
currentFatigue = previousFatigue × 0.5 ^ (elapsedHours / recoveryHalfLifeHours)
```

Пример для `recoveryHalfLifeHours = 24`:

```text
После тренировки: 80 / 100
Через 24 часа: 40 / 100
Через 48 часов: 20 / 100
Через 72 часа: 10 / 100
```

Это удобно, потому что усталость быстро падает в начале и медленнее приближается к нулю.

---

# Почему это работает при выключенном сервере

Нельзя уменьшать усталость только таймером в памяти.

Нужно хранить время последнего расчёта или события нагрузки в базе данных.

Если сервер был выключен 12 часов:

```text
lastFatigueCalculatedAt = 2026-05-14T08:00:00Z
nowUtc = 2026-05-14T20:00:00Z
elapsedHours = 12
```

При следующем запуске Forma пересчитает усталость сразу за все 12 часов.

---

# Event-based вариант

Лучше хранить не только текущий `fatigueScore`, но и события нагрузки.

```ts
type MuscleFatigueEvent = {
  id: string;
  userId: string;
  muscleId: string;

  source:
    | 'exercise_set'
    | 'exercise_summary'
    | 'workout_summary'
    | 'manual_adjustment';

  workoutId?: string;
  exerciseId?: string;
  setId?: string;

  occurredAt: string;
  fatigueDelta: number;

  role: 'primary' | 'secondary' | 'assisting' | 'stabilizer';
  note?: string;
};
```

Текущая усталость считается как сумма всех событий с учётом распада:

```text
currentFatigue = sum(
  event.fatigueDelta × 0.5 ^ (hoursSinceEvent / recoveryHalfLifeHours)
)
```

Такой подход автоматически учитывает выключение сервера, потому что используется реальный `occurredAt` каждого события.

# Snapshot для ускорения

Чтобы не пересчитывать все события каждый раз, можно хранить снимок:

```ts
type MuscleFatigueSnapshot = {
  userId: string;
  muscleId: string;
  fatigueScore: number;
  calculatedAt: string;
  recoveryHalfLifeHours: number;
  lastLoadAt?: string;
};
```

При чтении:

```text
1. Берём fatigueScore и calculatedAt.
2. Считаем elapsedHours = nowUtc - calculatedAt.
3. Уменьшаем fatigueScore по формуле восстановления.
4. Добавляем новые события нагрузки, если они есть.
5. Сохраняем новый snapshot с calculatedAt = nowUtc.
```

---

# Персонализация восстановления

`recoveryHalfLifeHours` может быть разным:

| Мышца / состояние | Пример |
| ----------------- | ------ |
| Малые мышцы | `18–24 ч` |
| Большие мышцы | `24–36 ч` |
| Очень тяжёлая тренировка | `36–48 ч` |
| Пользователь быстро восстанавливается | меньше |
| Пользователь отметил сильную усталость | больше |
| Был дискомфорт | больше |

Для MVP можно использовать:

```text
recoveryHalfLifeHours = 24
```

И позже персонализировать.

---

# Прогноз восстановления

Чтобы показать, когда мышца будет готова, нужно посчитать время до целевого уровня.

Цели:

| Цель | Значение |
| ---- | -------- |
| Полностью готова | `fatigueScore < 10` |
| Можно умеренно | `fatigueScore < 30` |
| Не высокая усталость | `fatigueScore < 60` |

Пример:

```text
Грудь: 72 / 100
До умеренной нагрузки: около 31 часа
До полной готовности: около 69 часов
```

---

# Что показывать в интерфейсе

В карточках и сводках:

```text
Грудь — высокая усталость · 72 из 100
Восстановление до умеренной нагрузки: ≈ 31 ч
```

На полном экране усталости:

```text
Грудь
Усталость: 72 из 100
Готовность: 28%
Последняя нагрузка: вчера, 19:20
Основные источники: жим с пола, отжимания
Прогноз: до лёгкой нагрузки ≈ 31 ч
```

Если усталость выше 100:

```text
Грудь
Усталость: 150 из 100
Статус: перегруз
Рекомендация: не нагружать грудь сегодня
```

# Ключевые требования

1. Усталость хранится числом `fatigueScore`.
2. `100` — граница очень высокой усталости, но значение может быть выше `100`.
3. Усталость повышается после упражнений по задействованным мышцам.
4. Усталость снижается по фактическому прошедшему времени.
5. Нельзя рассчитывать снижение только таймером в памяти.
6. Нужно хранить `calculatedAt` или события с `occurredAt`.
7. После выключения сервера усталость пересчитывается по разнице `nowUtc - calculatedAt` или `nowUtc - occurredAt`.
8. Для MVP достаточно `recoveryHalfLifeHours = 24`.
9. Для рекомендаций использовать уже пересчитанный `fatigueScore` на текущий момент.
10. В UI показывать и статус, и число: `72 из 100`.
