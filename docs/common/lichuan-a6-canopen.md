# Управление моментом двух приводов Lichuan A6 по CANopen

В паспорте тренажёра указаны приводы **LCDA6-10B2R17-LB922-CAN**. Для серии A6 производитель заявляет CiA 301, профиль приводов CiA 402 V2 и скорость до 1 Мбит/с. В Forma можно выбрать период обмена **20 мс (50 Гц), 10 мс (100 Гц) или 5 мс (200 Гц)**. За каждый цикл контроллер задаёт момент обеим осям и получает их положение, скорость и фактический момент. Период Modbus — 50 мс. Фактическая частота и отклик момента зависят от приводов, адаптера и компьютера. [Паспорт тренажёра, §2.8](../../plan/14-motor-control-v2.md#28-паспорт-железа-и-что-из-него-следует) · [Контроллер CANopen](../../backend/app/motor/drive/canopen.py) · [Lichuan, характеристики A6](https://en.xlichuan.com/product-xq/149.html)

## Как переключить Forma на другом компьютере

1. На управляющем компьютере с Linux подключить адаптер к шине обеих осей. Для **USB-CAN-FD-B** библиотеки из комплекта поставки входят в backend для x86-64, ARM64 и ARMhf. Программа выбирает библиотеку по архитектуре процесса. У пользователя, запускающего backend, должен быть доступ к USB-устройству. При отдельной установке совместимого SDK можно указать абсолютный путь через `CANOPEN_LIBRARY` в окружении процесса. Для адаптера **SocketCAN** сначала поднять сетевой интерфейс на скорости приводов, например `sudo ip link set can0 up type can bitrate 500000`. [Драйверы адаптеров](../../backend/app/motor/drive/can_bus.py)
2. Завершить тренировку, поставить гриф на механические упоры, выключить Servo ON на обеих осях. Установить параметры панели по таблице ниже. Проверить, что `6064` выдаёт отсчёты энкодера в масштабе профиля, и уточнить единицы `606C` у поставщика или контрольным перемещением на стенде.
3. В Forma открыть **Настройки → сервисный раздел → Подключение приводов** (`/settings/drives`). Выбрать **CANopen → Диагностика · только чтение → USB-CAN-FD-B**. Для первого подключения выбраны USB-устройство 0, **CAN1 на корпусе / SDK 0**, 500 кбит/с и Node ID 1 и 2. Сверить их с физической шиной и нажать **Применить режим**. Выбор сохраняется на этом компьютере. При пустой базе и `HARDWARE_ADAPTER=canopen` Forma тоже начинает с чтения. Ранее сохранённая рабочая конфигурация CANopen продолжает запускаться в режиме управления.
4. Дождаться **Канал открыт**, затем подать питание управления на каждый A6. Убедиться, что обе оси независимо отвечают на чтение `6041:00`. Снять отчёт по инструкции ниже. Для следующего этапа на стенде предусмотрено отдельное назначение **Управление приводами**. Выбрать подтверждённые единицы скорости, 500 кбит/с или 1 Мбит/с и начальный период 20 мс. В этом режиме Forma подготавливает пару и может автоматически включить Servo ON. Явное выключение оператором и авария привода требуют отдельного действия оператора.
5. До тренировки проверить на стенде направление, ноль, ограничение скорости и момента, действие потери SYNC и heartbeat и процедуру B1. Для возврата опереть гриф, выключить Servo ON, вернуть исходные параметры A6, перезапустить питание управления и выбрать **Modbus RTU** на том же экране.

В режиме управления контроллер сначала считывает состояние обеих осей и выбирает общий режим — CST, затем Profile Torque при поддержке на обеих сторонах. Он сверяет пределы `6072` и `6080`, проверяет или настраивает в оперативной памяти RPDO1 и два TPDO и проверяет принятую карту. Для включения обе оси должны вернуть записанный момент поддержки в `6071` и подтвердить переходы через `6041`. Для диагностики на стенде доступны `GET /api/hardware/drive-transport` и проверка B0. Master heartbeat использует Node ID 127 с периодом 100 мс. При доступном `1016` задаётся контроль мастера с тайм-аутом 300 мс либо сохраняется совместимая существующая настройка. Действие самой прошивки A6 при потере мастера следует проверить на механических упорах. [Реализация CANopen](../../backend/app/motor/drive/canopen.py)

## Что проверить при первом подключении

В режиме **Диагностика · только чтение** Forma открывает один канал и отправляет только запросы чтения SDO на два выбранных Node ID. На линии это стандартные 11-битные кадры Classical CAN. Первым байтом запроса будет `40`, для адресов 1 и 2 CAN-ID запросов равны `601` и `602`, ответов — `581` и `582`. Режим сохраняется после перезапуска. Двигатели могут получать питание в разное время. Опрос каждой оси возобновляется автоматически. Привод, который уже был включён другим контроллером, сохраняет своё состояние, поэтому сначала опереть гриф и выключить Servo ON. [CiA, доступ к словарю через SDO](https://www.can-cia.org/can-knowledge/sdo-protocol) · [CiA, состояния сети](https://www.can-cia.org/can-knowledge/network-management)

| Что видно на экране | Что проверить |
| --- | --- |
| Канал закрыт | Сверить USB-индекс, питание адаптера, права пользователя Ubuntu и текст ошибки SDK. После переподключения Forma повторяет открытие. |
| Канал открыт, ответила одна ось | Сверить S/N адаптера, разъём, адрес и скорость второй оси. На корпусе CAN1 соответствует SDK 0, CAN2 соответствует SDK 1. Оба A6 находятся на одном выбранном канале. |
| Есть heartbeat, чтение SDO даёт тайм-аут | Проверить последнее сетевое состояние и его возраст. Узел в Stopped отвечает на управление сетью. Состояние Pre-operational допускает чтение SDO. Период heartbeat производителя виден в `1017:00`. |
| Получен SDO abort | Узел ответил. В разделе **Словарь A6** видны адрес, код и возраст ответа. Например, `06020000` означает отсутствие объекта, `06090011` — отсутствие субиндекса. |
| Получен EMCY или установлен бит Fault в 6041 | Записать код и регистр из EMCY, значения `603F:00` и `1001:00` и код на панели самого A6. Нулевой EMCY обозначает сообщение о снятии ошибки. Условие Fault проверяется по текущему слову состояния. |
| Ответили обе оси | Снять **Сохранить отчёт JSON**. В него входят последние прочитанные значения, возраст, маска режимов, реальные параметры карт PDO, счётчики обмена и последние 64 успешные передачи или принятые кадры. Время кадров отмечает backend на компьютере. TX означает, что драйвер принял кадр на отправку. Получение данных приводом подтверждается его ответом. |

Состояние, позиция, скорость и момент опрашиваются примерно раз в секунду. Паспорт, настройки heartbeat, SYNC и карты PDO перечитываются примерно раз в 30 секунд, а также при новом соединении. Экран получает снимок каждые две секунды. В режиме управления отображаются данные циклических TPDO и уже выполненных SDO. Просмотр словаря, пауза журнала и сохранение отчёта читают имеющийся снимок. Значения у отключившегося узла показываются как последние полученные. Возраст указан в словаре для каждого объекта. Частота PDO и период p99 появляются после 20 полных интервалов обмена пары. [CiA, heartbeat и boot-up](https://www.can-cia.org/can-knowledge/error-control-protocols) · [CiA, SYNC и EMCY](https://www.can-cia.org/can-knowledge/special-function-protocols) · [CiA, типы и карты PDO](https://www.can-cia.org/can-knowledge/pdo-protocol)

По паспорту Waveshare у каждого канала есть **два** переключаемых резистора по 120 Ом. Если адаптер стоит на конце линии, включить **один** резистор выбранного канала, второй конец согласовать на последнем A6. Два включённых переключателя одного канала дают 60 Ом уже на самом адаптере. Для диагностики Forma предлагает скорости панели A6 в пределах паспортного диапазона адаптера. Фактическую совместимость выбранной скорости подтверждает ответ хотя бы одного A6. При первом пуске ориентир — 500 кбит/с, `PA_00C = 4`. На втором разъёме Waveshare отдельная шина. [Waveshare, характеристики, FAQ и Linux SDK](https://www.waveshare.com/wiki/USB-CAN-FD) · [Руководство A6, с. 37](../lichuan-a6-servo-driver-manualfull-version2020-05.pdf#page=41)

Штатные библиотеки для x86-64, ARM64 и ARMhf и заголовок SDK сверены с файлами архива Waveshare по SHA-256. При инициализации используется тип устройства 41 и приём всех стандартных CAN-ID на выбранном канале. Backend читает модель, серийный номер и версии через `ZCAN_GetDeviceInf`. Объекты CANopen передаются через `ZCAN_Transmit` и `ZCAN_Receive`. Настройка скорости фазы данных CAN FD в примере SDK относится к инициализации адаптера. Скорость кадров к A6 задаёт номинальная скорость канала. [Linux SDK Waveshare](https://files.waveshare.com/wiki/USB-CAN-FD/USB-CAN-FD-B-Linux.zip) · [Драйвер Forma](../../backend/app/motor/drive/can_bus.py)

## Запуск и отладка на Ubuntu

**Подготовка приложения.** На новой рабочей копии проекта под Ubuntu 24.04 создайте Linux-окружение из корня репозитория. Нужны Python 3.12 или новее, модуль `venv`, Node.js 22.12 или новее и npm. В комплекте Forma уже есть библиотека USB-CAN-FD-B. Для подготовленной установки достаточно команды запуска `bash start-watch.sh`. [Зависимости backend](../../backend/pyproject.toml) · [Требования Vite](https://vite.dev/guide/) · [Пакет python3-venv в Ubuntu](https://packages.ubuntu.com/noble/python3-venv)

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e './backend[dev,modbus,panel]'
npm --prefix frontend ci
bash start-watch.sh
```

После запуска откройте `http://127.0.0.1:5173/settings/drives`. Для полноэкранного запуска с Chromium из графической сессии есть `bash start-kiosk.sh`. Для **USB-CAN-FD-B** выберите одноимённый адаптер в Forma. Поле **Канал адаптера** показывает и маркировку разъёма на корпусе, и его индекс в SDK. Команда `lsusb` из пакета `usbutils` показывает USB-устройство и его адрес. Пользователь, запускающий Forma, должен иметь доступ на чтение и запись к соответствующему узлу `/dev/bus/usb/BBB/DDD`, где `BBB` и `DDD` — значения Bus и Device из `lsusb`. [Драйвер Forma](../../backend/app/motor/drive/can_bus.py) · [Пакет usbutils в Ubuntu](https://packages.ubuntu.com/noble/usbutils)

Если адаптер виден в `lsusb`, но у пользователя рабочего стола нет доступа к USB-узлу, можно создать файл `/etc/udev/rules.d/70-forma-usbcan.rules` с одной строкой. Замените `vvvv` и `pppp` четырьмя шестнадцатеричными цифрами производителя и устройства из колонки ID в `lsusb`. После `sudo udevadm control --reload-rules` переподключите адаптер при отключённом Servo ON и грифе на упорах. Для запуска от имени отдельной системной службы предоставьте USB-доступ её пользователю. [Правила udev](https://www.freedesktop.org/software/systemd/man/latest/udev.html)

```udev
SUBSYSTEM=="usb", ENV{DEVTYPE}=="usb_device", ATTR{idVendor}=="vvvv", ATTR{idProduct}=="pppp", TAG+="uaccess"
```

**Диагностика с подключёнными приводами.** Поле `diagnostics` содержит состояние канала, объекты и события каждой оси, счётчики и кадры. В режиме управления `nodes` содержит текущую обратную связь пары. Поля `timing.mean_hz` и `timing.p99_ms` дают измеренные частоту и период. Поле `timing.p99_feedback_ms` показывает 99-й процентиль времени от отправки SYNC компьютером до приёма всех четырёх TPDO, а `error` — причину ожидания или отказа. Журнал запуска доступен в том же каталоге проекта. Для адаптера с драйвером **SocketCAN** состояние Linux-интерфейса показывает `ip -details -statistics link show can0`, а трафик — `candump -tz can0` из пакета `can-utils`. [SocketCAN в Linux](https://docs.kernel.org/networking/can.html) · [Пакет can-utils в Ubuntu](https://packages.ubuntu.com/noble/can-utils)

```bash
curl -fsS http://127.0.0.1:8000/api/hardware/drive-transport | python3 -m json.tool
tail -F .runtime/backend-watch.log .runtime/backend-watch.log.err
```

**Отладка с точками останова.** Выберите в Forma **Цифровой двойник**. Пауза в потоке управления реальными A6 приостанавливает передачу SYNC и heartbeat. Скрипт `start-watch.sh` также перезапускает backend при изменении исходников. Для отдельной сессии с новой базой используйте `HARDWARE_ADAPTER=twin` и временный `DATABASE_URL`. Следующая команда из корня проекта запускает проверку CANopen без приводов. Тесты загружают штатную Linux-библиотеку, моделируют два узла и проверяют периоды 10 и 5 мс.

```bash
(
  cd backend
  can_test_dir=$(mktemp -d)
  APP_ENV=test HARDWARE_ADAPTER=twin HARDWARE_PANEL_ENABLED=false \
    DATABASE_URL="sqlite:///$can_test_dir/tests.sqlite" MEDIA_ROOT="$can_test_dir/media" \
    ../.venv/bin/python -m pytest -q app/tests/motor/test_canopen_drive.py
)
```

## Разъёмы и параметры панели A6

Для исполнения из руководства 2020-05 схема линии — **USB–CAN → левый A6 → правый A6**. На RJ45 **CN1/CN2** контакт **1 — CAN+ (H)**, **2 — CAN− (L)**, **3 — GND**. Контакты 4 и 5 используются для RS‑485. Включить оконечные сопротивления 120 Ом на двух физических концах линии. При такой топологии это адаптер и правый A6. На последнем приводе встроенный резистор CAN подключает перемычка **CN3, контакты 31–32**. Контакты 33–34 относятся к RS‑485. На актуальной веб-странице A6 разъёмы CAN обозначены **CN6A/CN6B**. Перед изготовлением кабеля сверить маркировку обоих приводов. Если на корпусе CN6A/CN6B, нужна распиновка этого исполнения. [Руководство A6, печатные с. 9 и 11](../lichuan-a6-servo-driver-manualfull-version2020-05.pdf#page=13) · [Карточка серии](https://en.xlichuan.com/product-xq/149.html) · [CiA, согласование линии CAN](https://www.can-cia.org/fileadmin/cia/documents/brochures/can_dictionary_v12.pdf)

| Параметр | Значение для стенда | Назначение |
| --- | --- | --- |
| `PA_000` | Левый `1`, правый `2` | Общий адрес CANopen и RS‑485. Назначить разные адреса и сверить стороны поочерёдным включением с грифом на опорах. |
| `PA_002` | `10` на обоих | Выбор CANopen. В таблице режимов A6 явно указано значение 10, хотя соседняя колонка диапазона заканчивается на 5. |
| `PA_00C` | `4` на обоих для первого теста | Скорость CAN. Значения `0 / 1 / 2 / 3 / 4 / 5 / 6` дают соответственно 20 / 50 / 125 / 250 / 500 / 750 / 1000 кбит/с. Заводское значение — `4`. Адаптер выставляется на ту же скорость. |
| `PA_00D` | Текущее значение | Скорость порта RS‑485. |

Перед переключением записать текущие параметры обеих осей. Для первого подключения опустить и механически опереть гриф, освободить зону движения и явно выключить Servo ON для обеих осей в Forma. Сохранить настройку с панели и перезапустить питание управления для применения `PA_002` и `PA_00C`. Версию ПО можно посмотреть в режиме индикации 6 (`PA_001`). В режиме Modbus программа проверяет `PA_002 = 2` и управляет Servo ON через виртуальный вход. Для возврата к Modbus восстановить исходные параметры и перезапустить питание управления. [Руководство A6, печатные с. 35, 37 и 66](../lichuan-a6-servo-driver-manualfull-version2020-05.pdf#page=39) · [Проверки Modbus в проекте](../../backend/app/motor/drive/registers.py)

## Первое подключение и чтение возможностей приводов

Примеры даны для отдельного адаптера **Classic CAN** под Linux с SocketCAN и утилитами `can-utils`. Для Windows в программе USB–CAN адаптера выбирают стандартный 11-битный идентификатор и те же байты данных. Для интерфейса `can0`, который сейчас опущен, запустить монитор до включения питания управления приводов. [SocketCAN](https://docs.kernel.org/networking/can.html) · [can-utils](https://github.com/linux-can/can-utils)

```sh
sudo ip link set can0 type can bitrate 500000
sudo ip link set can0 up
candump -tz can0
```

При загрузке узлов 1 и 2 ожидаются кадры `701#00` и `702#00`. Если узел уже включён, этот разовый кадр можно пропустить. Узел в состоянии *Pre-operational* уже отвечает на SDO — запросы чтения и настройки. После настройки периодического heartbeat на тех же идентификаторах байт `7F` означает *Pre-operational*, `05` — *Operational*, `04` — *Stopped*. [CiA, управление состоянием сети](https://www.can-cia.org/can-knowledge/network-management) · [CiA, boot-up и heartbeat](https://www.can-cia.org/can-knowledge/error-control-protocols)

Для ручной проверки остановить контроллер Forma, чтобы на шине работал один мастер. В другом терминале отправлять по одному запросу и дожидаться ответа. Например, так читается `0x6502:00`, маска поддерживаемых режимов, сначала у левого, затем у правого привода.

```sh
cansend can0 601#4002650000000000
# После ответа на ID 581
cansend can0 602#4002650000000000
```

В таблице приведены готовые аргументы для `cansend can0`. По умолчанию запрос узлу 1 идёт на `601`, ответ на `581`. Для узла 2 заменить только идентификатор запроса на `602` и ждать ответ на `582`. В кадрах все числа шестнадцатеричные, индекс и числовые данные идут младшим байтом вперёд. [CiA, SDO](https://www.can-cia.org/can-knowledge/sdo-protocol) · [Адреса SDO в canopen-python](https://canopen.readthedocs.io/en/stable/_modules/canopen/node/remote.html)

| --- | --- | --- |
| Идентификатор производителя | `0x1018:01` | `601#4018100100000000` |
| Код изделия | `0x1018:02` | `601#4018100200000000` |
| Ревизия изделия | `0x1018:03` | `601#4018100300000000` |
| Поддерживаемые режимы | `0x6502:00` | `601#4002650000000000` |
| Состояние силового привода | `0x6041:00` | `601#4041600000000000` |
| Текущий режим работы | `0x6061:00` | `601#4061600000000000` |
| Фактическая позиция | `0x6064:00` | `601#4064600000000000` |
| Фактическая скорость | `0x606C:00` | `601#406C600000000000` |
| Фактический момент | `0x6077:00` | `601#4077600000000000` |
| COB-ID первого приёмного PDO | `0x1400:01` | `601#4000140100000000` |
| Число полей и первое поле приёмного PDO | `0x1600:00`, `0x1600:01` | `601#4000160000000000`, `601#4000160100000000` |
| Число полей первого и второго передающих PDO | `0x1A00:00`, `0x1A01:00` | `601#40001A0000000000`, `601#40011A0000000000` |

Пример для проверки декодера. Ответ `581#4B41600040000000` на чтение `0x6041:00` возвращает двухбайтовое значение `0x0040` — *Switch on disabled*. Для короткого ответа `4F`, `4B` и `43` означают 1, 2 и 4 байта соответственно. Байт `80` обозначает отказ SDO. Последние четыре байта дают код причины, например `0x06020000` — объект отсутствует, `0x06040041` — объект нельзя включить в PDO. Тайм-аут и полученный отказ SDO нужно записывать отдельно. [Коды отказов SDO](https://canopen.readthedocs.io/en/stable/_modules/canopen/sdo/exceptions.html) · [Маски CiA 402](https://canopen.readthedocs.io/en/stable/_modules/canopen/profiles/p402.html)

В доступном комплекте документации для **LB922-CAN** нет EDS — файла с описанием объектов этой ревизии. После чтения `0x1018` у Lichuan можно запросить **A6-CAN CANopen communication manual** и **EDS** с совпадающими кодом изделия и ревизией. Если прошивка хранит EDS в необязательном объекте `0x1021:00`, его можно получить сегментированным чтением SDO. Для выбора режима нужны также минимальный период SYNC, частота обновления обратной связи, единицы величин и действие при потере управляющих кадров. [Каталог документации Lichuan](https://en.xlichuan.com/download/9.html) · [Чтение EDS из узла](https://canopen.readthedocs.io/en/stable/network.html)

## Режим момента и единицы

В настройках подключения раскройте **Режим момента и подключение A6**. По умолчанию Forma запрашивает CST и при необходимости пробует Profile Torque. Для проверки конкретного режима можно выбрать **Только CST (10)** или **Только Profile Torque (4)**. Выбор действует при запуске управления и требует подтверждения `6061:00` от обеих осей. При несовместимости запуск остановится до начала передачи уставок. В диагностике выбор сохраняется для следующего этапа, а текущий режим показывает словарь.

Параметр панели `PA_002 = 10` включает управление по CANopen. После этого объект **`0x6060:00`** выбирает рабочий режим внутри CiA 402. Номера параметров A6 и индексы словаря CANopen принадлежат разным адресным пространствам. Например, в существующем Modbus-контроллере задание момента записывается в `PA_12C`, а стандартный объект CANopen для него — `0x6071:00`. Проверять поддержку на **каждой** оси. [Руководство A6, печатная с. 35](../lichuan-a6-servo-driver-manualfull-version2020-05.pdf#page=39) · [CiA, профиль 402](https://www.can-cia.org/can-knowledge/cia-402-series-canopen-device-profile-for-drives-and-motion-control) · [Карта Modbus тренажёра](../../backend/app/motor/drive/registers.py)

| Режим CiA 402 | Что искать в `0x6502` | Что проверить |
| --- | --- | --- |
| Profile Torque, `0x6060 = 4` | Бит 3, маска `0x00000008` | Команда момента `0x6071`. Если реализован `0x6087`, его значение задаёт темп изменения момента. Слишком пологая рампа останется заметной и при частых командах. |
| Cyclic Synchronous Torque (CST), `0x6060 = 10` | Бит 9, маска `0x00000200` | Команда момента `0x6071`, синхронное применение уставок, допустимые периоды SYNC. Это предпочтительный вариант для двух осей, если прошивка его поддерживает. |

При отключённой силовой части можно выбрать **подтверждённый** режим. Пример записи Profile Torque на узле 1 — `601#2F60600004000000`. Для CST значение в том же поле — `0A`, кадр `601#2F6060000A000000`. Ответ `581#6060600000000000` подтверждает запись. Затем прочитать `0x6061:00` и дождаться фактического значения `04` или `0A`. Если `0x6502` отсутствует, режим устанавливают по EDS или руководству ревизии и проверяют через `0x6061`. Одна лишь доступность `0x6071` по SDO ещё оставляет открытым вопрос о его передаче в PDO. [Режимы и маски CiA 402](https://canopen.readthedocs.io/en/stable/_modules/canopen/profiles/p402.html) · [Определение Torque slope](https://doc.synapticon.com/node/sw5.1/objects_html/6xxx/6087.html)

Если обе оси поддерживают только Profile Torque, выбранный цикл обмена также используется при доступном `0x6071` в RPDO. Ступенчатая проба покажет, успевает ли момент отработать команды с заданной рампой. Если заводская карта не содержит уставку или обратную связь и переназначение недоступно, потребуется поддерживаемая производителем карта для этой версии A6. [CiA, фиксированные и изменяемые карты PDO](https://www.can-cia.org/can-knowledge/pdo-protocol/)

В стандартном представлении `0x6071:00` (заданный момент) и `0x6077:00` (фактический момент двигателя) — знаковые 16-битные числа в тысячных номинального момента. При подтверждённом масштабе и паспортных 4 Н·м значение `+100` соответствует +0,4 Н·м **на валу**. Для силы на грифе приложение использует калибровку и направление каждой стороны. Позиция `0x6064:00` и скорость `0x606C:00` — знаковые 32-битные числа. Проверить единицы каждого по известному перемещению и времени, сопоставить направления и ноль энкодера с действующим профилем. Перенос ограничений момента и скорости из `PA_05E` и `PA_056` требует проверки их действия в выбранном режиме CANopen. [Задание момента](https://doc.synapticon.com/node/sw5.1/objects_html/6xxx/6071.html) · [Обратная связь по моменту](https://doc.synapticon.com/node/sw5.1/objects_html/6xxx/6077.html) · [Преобразования действующего привода](../../backend/app/motor/drive/lichuan.py)

## Циклические команды и обратная связь

SDO нужны при запуске и диагностике. Для тренировки данные передаются в PDO — коротких кадрах без отдельного запроса к каждому регистру. Направление указывается со стороны привода. Ниже **предлагаемая карта** при поддержке этих объектов и типов передачи. Заводскую карту LB922-CAN нужно прочитать с обоих узлов. [CiA, параметры и отображение PDO](https://www.can-cia.org/can-knowledge/pdo-protocol/)

| Кадр на одну ось | Поля по порядку | Значения записей карты | Пример CAN-ID для осей 1 / 2 |
| --- | --- | --- | --- |
| RPDO1, ПК → привод, 4 байта | Управляющее слово `0x6040` (U16), задание момента `0x6071` (I16) | `60400010`, `60710010` | `201 / 202` |
| TPDO1, привод → ПК, 8 байт | Позиция `0x6064` (I32), скорость `0x606C` (I32) | `60640020`, `606C0020` | `181 / 182` |
| TPDO2, привод → ПК, 4 байта | Фактический момент `0x6077` (I16), состояние `0x6041` (U16) | `60770010`, `60410010` | `281 / 282` |

Пример для офлайн-проверки кодирования RPDO1 по этой карте. В кадре `201#0F001900` первые два байта задают управляющее слово `0x000F`, следующие два — момент `+25`. В кадре `202#0F00E7FF` то же слово сопровождает момент `−25`. Это тестовые числа для проверки знака и порядка байтов. Рабочую команду для каждой стороны рассчитывают из её калибровки и проверенного момента поддержки.

1. В NMT *Pre-operational* прочитать параметры `0x1400`, `0x1800`, `0x1801`. Субиндекс `:01` даёт COB-ID. Установленный бит 31 означает, что PDO отключён. Субиндекс `:02` задаёт тип передачи. В `0x1600`, `0x1A00`, `0x1A01` прочитать счётчик `:00` и все записи от `:01` до счётчика. В каждой записи старшие 16 бит — индекс, следующие 8 — субиндекс, младшие 8 — длина в битах. Для фиксированной карты строить кадры в порядке, который возвращает привод.
2. Если прошивка разрешает переназначение, сохранить исходную карту. Для каждого изменяемого PDO установить бит 31 его COB-ID, обнулить счётчик карты, записать поля, вернуть их количество, установить поддерживаемый тип передачи и снова разрешить PDO снятием бита 31. Прочитать результат обратно. Для обратной связи каждый такт нужен синхронный TPDO с типом `1` либо другой подтверждённый режим, выдающий свежие данные с нужным периодом. [CiA, процедура изменения карты](https://www.can-cia.org/can-knowledge/pdo-protocol/)
3. После проверки конфигурации мастер переводит узлы в NMT *Operational* по одному, кадрами `000#0101` и `000#0102`. Это разрешает обмен PDO. Силовое включение имеет собственный автомат CiA 402. Для настройки на закреплённом стенде возврат в *Pre-operational* по узлам задают `000#8001` и `000#8002`. [CiA, NMT](https://www.can-cia.org/can-knowledge/network-management)
4. При синхронных RPDO мастер передаёт две уставки **до ближайшего SYNC** и следит, чтобы оба кадра успевали выйти на шину. SYNC имеет высокий приоритет CAN и может обогнать ещё стоящие в очереди команды. При стандартных настройках один мастер посылает `080#` без данных, приводы применяют принятые уставки на границе цикла и передают настроенные TPDO. COB-ID SYNC задаёт `0x1005`. При ненулевом `0x1006` Forma сверяет период в микросекундах — 20 000, 10 000 или 5 000 соответственно. Приводы с внешним SYNC могут работать с нулевым или отсутствующим `0x1006`. Рабочий цикл проверяется по фактическим ответам обоих узлов. [CiA, SYNC](https://www.can-cia.org/can-knowledge/special-function-protocols) · [Обработка синхронного RPDO](https://canopennode.github.io/CANopenNode/group__CO__PDO.html) · [Объекты связи](https://canopennode.github.io/CANopenNode/md_example_2DS301__profile.html)

Для этой карты один такт содержит семь кадров — два с уставками, один SYNC и четыре с обратной связью. При стандартных 11-битных идентификаторах и без повторных передач это ориентировочно **1,2–1,4 мс на линии при 500 кбит/с** или **0,6–0,7 мс при 1 Мбит/с**. Расчёт учитывает межкадровые интервалы и заполнение битами. Сверх этого времени добавятся USB, планировщик ПК, обновление измерений внутри A6 и механическая реакция. Поэтому 500 кбит/с — разумная исходная скорость уже для проверки цикла 20 мс. [Расчёт длины классического CAN-кадра в Linux](https://github.com/torvalds/linux/blob/master/include/linux/can/length.h)

## Включение пары и реакция на ошибки

Для автомата CiA 402 команда записывается в `0x6040:00`, состояние читается из `0x6041:00`. При пуске с грифом на механических опорах сначала проверить границы момента и скорости, режим, знаки, готовность обеих осей и способ заранее задать каждой проверенный поддерживающий момент. Состояние каждого привода подтверждать по статусу перед следующим переходом. [Автомат CiA 402](https://canopen.readthedocs.io/en/stable/_modules/canopen/profiles/p402.html) · [Требования безопасности тренажёра, R1–R6](../../backend/app/motor/SAFETY_REQUIREMENTS.md)

| Переход | Значение `0x6040` | Ожидаемый результат |
| --- | --- | --- |
| Shutdown → Ready to switch on | `0x0006` | `(status & 0x006F) == 0x0021` |
| Switch on → Switched on | `0x0007` | `(status & 0x006F) == 0x0023` |
| Enable operation → Operation enabled | `0x000F` | `(status & 0x006F) == 0x0027` |

Вне тренировки программа ждёт оба узла. Затем проверяет конфигурацию, свежесть данных, отсутствие аварий и состояние кнопки СТОП. При готовности обеих сторон задаёт каждой момент поддержки с её знаком, включает пару, проверяет оба статуса и снимает сообщение ожидания. Если вторая ось не подтверждает включение, программа отправляет команду отключения обеим осям, которые пыталась включить. Ручной Servo OFF и нажатый СТОП блокируют автовключение. Во время тренировки или калибровки потеря оси прерывает текущую операцию и фиксирует ошибку до явного сброса. [Логика восстановления пары](../../backend/app/services/hardware_runtime.py) · [Требования R1–R6](../../backend/app/motor/SAFETY_REQUIREMENTS.md)

При `(status & 0x004F) == 0x0008` привод в состоянии *Fault*. Сохранить EMCY (типовые CAN-ID `081 / 082`), общий регистр ошибок `0x1001` и код привода `0x603F`, если доступен. После устранения причины сброс CiA 402 выполняется фронтом бита 7 управляющего слова по явной команде оператора. Уведомление об ожидаемом позднем питании снимается по готовности пары без такого сброса. [CiA, EMCY](https://www.can-cia.org/can-knowledge/special-function-protocols) · [Состояния CiA 402](https://canopen.readthedocs.io/en/stable/_modules/canopen/profiles/p402.html)

Для контроля связи `0x1017` задаёт период исходящего heartbeat привода в мс. Контроль мастера самим приводом требует heartbeat от мастера, настройки его приёма через `0x1016` при поддержке A6 и известного действия по тайм-ауту. Отдельно проверить потерю только RPDO или SYNC при продолжающемся heartbeat, пропажу одного TPDO, отключение одного привода и потерю самого ПК. На вертикальной оси без тормоза снятие момента освобождает гриф. Результат каждого отказа нужно проверить с механической опорой до тренировки. [CiA, контроль узлов](https://www.can-cia.org/can-knowledge/error-control-protocols) · [Параметры heartbeat](https://canopennode.github.io/CANopenNode/md_example_2DS301__profile.html) · [Действие при потере удержания](../../backend/app/motor/SAFETY_REQUIREMENTS.md)

## Проверка выигрыша на тренажёре

При первом испытании ускоренного обмена поставить гриф на упоры, выключить Servo ON и выбрать **10 мс**. При 100 Гц обе оси должны прислать четыре TPDO в течение 7 мс после каждого рабочего SYNC. Если обмен устойчив, тем же способом проверить **5 мс**. При 200 Гц окно ответов составляет 3,5 мс. На быстрых режимах Forma проверяет несколько последовательных обменов до автоматического включения. При пропуске экран показывает идентификатор недостающего TPDO. [Контроллер CANopen](../../backend/app/motor/drive/canopen.py)

На экране **Подключение приводов → Обмен двух приводов** видны средняя частота и p99 периода. Статистика появляется после 20 интервалов и охватывает до 200 последних полных циклов. Метки ставит управляющий ПК в момент отправки SYNC. Для проверки редких задержек и разницы во времени ответов осей запустить **B1** на выбранном периоде. Для оценки отклика момента на упорах запустить **B2**. Она измеряет время от команды до достижения 63 % её ступени по обратной связи момента. В режиме Profile Torque на это время влияет также настроенная в приводе рампа. [Измерение отклика момента](../../backend/app/motor/calibration/procedures/drive_response.py) · [Измерение времени шины](../../backend/app/motor/calibration/procedures/bus.py)
