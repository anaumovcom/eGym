# Экран 17 — Усталость / карта мышц

## Назначение экрана

Экран **“Усталость / карта мышц”** нужен, чтобы пользователь видел текущее состояние восстановления мышц:

```text
Какие мышцы готовы к нагрузке?
Какие частично устали?
Какие лучше сегодня не нагружать?
Почему мышца устала?
Когда она восстановится?
Какие упражнения повлияли на усталость?
Что лучше тренировать сегодня?
```

Это один из ключевых экранов Forma, потому что он помогает не просто тренироваться, а **разумно распределять нагрузку**.

---

# Связь с универсальными компонентами

Карта мышц на этом экране должна использовать общий компонент `MuscleMap`.

Каноническое описание режимов, вариантов, статусов и поведения клика находится в:

```text
docs/common/ui-components.md
```

Каноническая модель расчёта усталости, прироста после упражнений и восстановления со временем находится в:

```text
docs/common/muscle-fatigue-model.md
```

Этот документ описывает полный экран **“Усталость / карта мышц”** и сценарии анализа восстановления, а не отдельную реализацию компонента.

---

# Главное архитектурное решение

Карту мышц нужно делать не как часть одного экрана, а как переиспользуемую компоненту:

```text
MuscleMap
```

или более точно:

```text
MuscleFatigueMap
```

Она должна использоваться на разных экранах:

| Экран                           | Как используется карта                        |
| ------------------------------- | --------------------------------------------- |
| **Главная**                     | Подробная карта текущей усталости.            |
| **Усталость**                   | Полный экран анализа восстановления мышц.     |
| **Прогресс → Мышцы**            | Карта нагрузки за период.                     |
| **Итог тренировки**             | Карта мышц, нагруженных на тренировке.        |
| **Карточка упражнения → Мышцы** | Карта мышц, участвующих в упражнении.         |
| **Конструктор тренировок**      | Баланс мышц в программе.                      |
| **Сегодняшняя тренировка**      | Какие мышцы будут нагружены планом.           |
| **Библиотека программ**         | Совместимость программы с текущей усталостью. |

---

# Важно: карта может работать в разных режимах

Одна и та же компонента должна поддерживать разные режимы отображения.

## Режим 1 — Усталость сейчас

Для экрана **“Усталость”** и **главной страницы**.

```text
Грудь — высокая усталость
Спина — готова
Ноги — лёгкая усталость
Бицепс — средняя усталость
```

---

## Режим 2 — Нагрузка за период

Для экрана **“Прогресс → Мышцы”**.

```text
Спина — высокая нагрузка за 30 дней
Грудь — средняя нагрузка
Плечи — низкая нагрузка
Кор — почти не нагружался
```

---

## Режим 3 — Мышцы упражнения

Для **карточки упражнения**.

```text
Основные мышцы:
грудь

Дополнительные:
трицепс

Стабилизаторы:
кор, передняя дельта
```

---

## Режим 4 — Нагрузка тренировки

Для **итога тренировки** и **сегодняшней тренировки**.

```text
Сегодня тренировка нагрузит:
спину, бицепс, предплечья

Почти не затронет:
грудь, ноги, трицепс
```

Для режима **усталости**:

| Цвет      | `fatigueScore` | Состояние         | Значение                    |
| --------- | -------------- | ----------------- | --------------------------- |
| Зелёный   | `0–9`          | Готова            | Можно тренировать.          |
| Жёлтый    | `10–29`        | Лёгкая усталость  | Можно тренировать умеренно. |
| Оранжевый | `30–59`        | Средняя усталость | Лучше снизить нагрузку.     |

# Экран “Усталость / карта мышц”

## Основная задача экрана

Показать полную информацию о текущем восстановлении мышц.

Пользователь должен открыть экран и понять:

```text
Сегодня грудь и трицепс лучше не грузить.
Спина и ноги готовы.
Можно сделать тренировку на спину, ноги или лёгкий кор.
```

# Как считать усталость

У каждой мышцы должен быть числовой показатель:

```text
fatigueScore
```

В интерфейсе он отображается так:

```text
Усталость: 7 из 100
Усталость: 72 из 100
Усталость: 150 из 100
```

`100` — граница очень высокой усталости. Значение может быть выше `100`, если мышца перегружена.

Усталость повышается после упражнений и снижается по фактическому прошедшему времени.

Важно:

```text
Если сервер был выключен, усталость всё равно должна снизиться.
Для этого расчёт использует nowUtc - lastFatigueCalculatedAt
или nowUtc - occurredAt для событий нагрузки.
```

Подробная формула и event-based модель описаны в:

```text
docs/common/muscle-fatigue-model.md
```

На уровне интерфейса можно не показывать сложную формулу, но логика должна учитывать:

```text
какие упражнения выполнялись;
какие мышцы участвовали;
роль мышцы в упражнении;
объём нагрузки;
интенсивность;
количество подходов;
качество выполнения;
время с последней нагрузки;
субъективную сложность;
дискомфорт;
историю восстановления пользователя.
```

---

# Снижение усталости со временем

Рекомендуемая модель:

```text
currentFatigue = previousFatigue × 0.5 ^ (elapsedHours / recoveryHalfLifeHours)
```

Для MVP:

```text
recoveryHalfLifeHours = 24
```

Пример:

```text
После тренировки: 80 из 100
Через 24 часа: 40 из 100
Через 48 часов: 20 из 100
Через 72 часа: 10 из 100
```

Расчёт должен выполняться при каждом открытии экрана усталости, главной, сегодняшней тренировки, календаря, библиотеки программ и при генерации рекомендаций.

# Рост усталости после упражнения

После упражнения создаются события нагрузки по каждой мышце.

Пример:

```text
Тяга сверху

Спина: +28
Бицепс: +17
Предплечья: +9
Кор: +4
```

Пример после пересчёта:

```text
До упражнения:
спина — 12 из 100

После упражнения:
спина — 40 из 100

Через 24 часа:
спина — 20 из 100
```

Если упражнение выполнено тяжело или сверх плана, прирост выше. Если упражнение выполнено частично, прирост ниже.

# Ключевые требования

1. Карта мышц должна быть переиспользуемой компонентой.
2. Компонента должна поддерживать режимы: усталость, нагрузка периода, мышцы упражнения, нагрузка тренировки.
3. Карта должна показывать тело спереди и сзади.
4. Карта должна быть интерактивной.
5. При выборе мышцы открывается подробная панель.
6. Цвета должны зависеть от режима карты.
7. Экран “Усталость” показывает текущую готовность мышц.
8. Экран должен объяснять, почему мышца устала.
9. Нужно показывать ожидаемое восстановление.
10. Нужно показывать упражнения, которые повлияли на усталость.
11. Нужно рекомендовать, что можно тренировать сегодня.
12. Нужно показывать, какие упражнения лучше отложить.
13. Экран должен использоваться вместе с каталогом, календарём, конструктором и главной.
14. Не нужно давать медицинских оценок.
15. Интерфейс должен быть крупным, понятным и удобным для 4K-монитора.
