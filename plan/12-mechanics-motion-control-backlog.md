# Этап 12 — Доработки механики и управления движением грифа

## Цель

Собрать в одном месте всё, что нужно доработать в части реальной работы с механикой: двумя ШВП, приводами, грифом и нагрузкой. Сейчас `hardware_runtime` — эмулятор с фиксированными скоростями, без учёта нагрузки и без контроля перекоса; safety-gate проверяет статусы, но не физику движения.

Текущее состояние (для ориентира):

* движение — линейное «пинг-понг» между `lower_bound_mm` и `upper_bound_mm` с постоянной скоростью;
* `sync_delta_mm` считается, но никак не корректируется (только `machine_state = warning` при > 5 мм);
* `torque_limit_percent` захардкожен (72), не зависит от веса/режима нагрузки;
* лимиты хода зашиты (0–2100 мм), профили движения из настроек не применяются к движению;
* `loadMode` (`assist_up`, `negative_phase`, `light_mode` и т.д.) существует только на уровне UI/схем и не влияет на приводы;
* нет понятия «стартовое положение» и процедуры выхода в него.

---

## 1. Стартовое положение и подготовка к упражнению

- [x] **Выход грифа в стартовую позицию** перед подходом (`move_to_start`): целевая точка — нижняя или верхняя точка калибровки в зависимости от типа упражнения (жим — снизу, тяга — сверху). Хранить `startPoint: 'lower' | 'upper' | 'custom'` в калибровке.
- [x] **Настраиваемое усилие удержания в стартовой позиции** («предварительный натяг»): гриф удерживается с заданным моментом, чтобы пользователь ощущал сопротивление до старта, но мог его сдвинуть. Параметры: `startHoldTorquePercent`, `startHoldToleranceMm`. Уровни для UI: очень низкий / низкий / средний, числа — в инженерном режиме.
- [x] **Скорость и профиль подвода** — отдельный профиль `return` («Скорость возврата» из документации), низкий момент, плавный старт/остановка.
- [x] **Детекция захвата грифа** пользователем (по отклонению позиции/росту тока) → переход из «удержание» в «тренировка». Настраиваемый порог `gripDetectDeltaMm` / `gripDetectCurrentA`.
- [ ] **Обратный отсчёт / подтверждение перед выходом в стартовую точку** — движение только после подтверждения свободной зоны, с возможностью прервать (СТОП, отпускание кнопки).
- [x] **Возврат в парковочную позицию** после подхода/тренировки (`park`) с отдельными настройками позиции и скорости.

### 1.1. Режим фиксированной позиции грифа (подтягивания, отжимания, опора)

- [x] **Режим `fixed_position`** в `loadMode`/`machineMode`: гриф выводится в заданную высоту и жёстко удерживается (`position_hold` с максимальным моментом), движения нет — тренажёр работает как турник / упор для отжиманий / опора для выпадов и т.п.
- [x] **Параметр высоты фиксации в калибровке упражнения**: `fixedPositionMm` вместо пары нижняя/верхняя точка; тип калибровки `position_check`. Отдельные пресеты «Турник» (высота по росту пользователя, рука вытянута вверх + запас), «Упор для отжиманий», «Австралийские подтягивания» (низкий турник), «Опора для приседа/выпадов».
- [ ] **Подбор высоты по профилю пользователя**: предложить `fixedPositionMm` из роста (`heightCm`) и сохранённого значения прошлых подходов; пользователь корректирует кнопками ±1/±5 см, значение запоминается в калибровке.
- [x] **Проверка удержания перед стартом**: после выхода в позицию — тест удержания (нет дрейфа под нагрузкой N секунд), проверка синхронности сторон, только затем `canStart`. Динамическая нагрузка от веса тела (рывок при подтягивании) не должна сдвигать гриф — контроль `positionDriftMm` с автоподстройкой.
- [x] **Безопасность в режиме фиксации**: запрет любых команд движения во время подхода (в т.ч. `manual_move`, `start_motion`); допустимая нагрузка проверяется по весу пользователя (`bodyWeightKg` + отягощение) относительно `max_load`; при потере связи/E-STOP — сохранять удержание (тормоз), а не отпускать.
- [x] **Учёт нагрузки в фиксации**: рост тока удержания превышает лимит (пользователь тяжелее допустимого или рывок) → предупреждение, а не сброс позиции; порог `holdOverloadCurrentA` настраиваемый.
- [x] **Счёт повторов без движения грифа**: для подтягиваний/отжиманий повторы считать по датчику усилия (колебания тока/нагрузки удержания по фазам) либо вручную/по таймеру; хранить `repCountSource: 'motion' | 'load' | 'manual' | 'timer'`.
- [ ] **Выход из режима**: после подхода — гриф остаётся в фиксации до подтверждения пользователя («Гриф свободен»), затем плавный переход в парковку/следующее упражнение.
- [ ] **Переключение между упражнениями** в тренировке: если следующее упражнение тоже с фиксацией, но на другой высоте — перемещение с подтверждением свободной зоны, низкая скорость, детекция препятствия.

## 2. Синхронизация сторон и защита от перекоса

- [x] **Активное выравнивание в движении** — регулятор (ведущий/ведомый или параллельный с коррекцией): ведомая сторона подтягивается к ведущей, коррекция ограничена `syncCorrectionMaxMmPerSec`. Хранить выбранную схему `syncMode: 'master_slave' | 'parallel'`.
- [x] **Настраиваемые пороги рассинхрона** с безопасными ограничениями (по документации: 0–2 норма, 2–5 допустимо, 5–8 предупреждение, >8 блокировка). Сейчас в коде один порог 5 мм и он не берётся из настроек `sync_limit`.
- [x] **Действие при критическом рассинхроне** по `desync_action`: замедлить / удержать позицию / аварийный стоп. Сейчас настройка сохраняется, но не используется.
- [x] **Учёт асимметричной нагрузки**: пользователь давит одной стороной сильнее — корректировать момент по сторонам, а не только позицию; показывать асимметрию усилий в live-телеметрии (`leftForcePercent` / `rightForcePercent`).
- [x] **Процедура «Выровнять стороны»** в сервисном режиме: медленно, низким моментом, по удержанию кнопки, с PIN; фиксировать результат в audit log.
- [x] **Проверка синхронности при homing и старте** — до начала подхода стороны должны быть в допуске, иначе автоматическое выравнивание или блокировка.
- [ ] **Инверсия направления сторон** (`leftDirectionInverted` / `rightDirectionInverted`) и передаточное отношение — применять при пересчёте оборотов в мм.

## 3. Режимы нагрузки и управление моментом

- [x] **Реализовать `loadMode` на уровне приводов**:
  * `normal_weight` — сопротивление эквивалентно весу (пересчёт кг → момент через шаг ШВП, КПД, передаточное отношение);
  * `assist_up` — помощь на подъёме, полное сопротивление на опускании;
  * `negative_phase` — усиленная эксцентрика (повышенный момент на опускании), ограничение сверху по безопасности;
  * `light_mode` — сниженный момент и скорость;
  * `bodyweight` / `no_machine` — приводы в удержании/парковке.
- [x] **Пересчёт кг → момент/ток** с калибровочным коэффициентом (`kgToTorqueFactor`) и процедурой проверки эталонным грузом; хранить в инженерных настройках.
- [x] **Компенсация трения и веса самого грифа**, чтобы «40 кг» ощущались как 40 кг в обоих направлениях. Отдельные коэффициенты для подъёма и опускания.
- [x] **Режим «невесомый гриф» (gravity compensation / zero-load)**: двигатели постоянно создают момент, равный весу грифа и подвижных частей (`barMassKg`, `movingPartsMassKg` на сторону), так что гриф ощущается как ничего не весящий и остаётся на месте, куда его отпустили. Используется как база для всех режимов нагрузки (заданный вес = компенсация + добавочный момент), для `light_mode`, разминки, реабилитации, показа диапазона, свободного перемещения при калибровке и ручной установки высоты в `fixed_position`. Параметры: `gravityCompensationEnabled`, `barMassKg` (измеряется сервисной процедурой — удержание в покое, ток удержания → масса), `gravityCompensationGain` (0–100 %, чтобы можно было оставить часть веса, например «гриф весит 5 кг»), отдельная поправка на трение направляющих. Требования безопасности: при отключении компенсации/ошибке — переход в удержание, а не свободное падение; обязательна проверка после смены навесного оборудования (изменилась масса → пересчёт или предупреждение); ограничение максимальной скорости дрейфа в «невесомом» состоянии.
- [x] **Компенсация инерции ШВП и роторов двигателей**: при старте движения из покоя и при смене направления (верхняя/нижняя точка повтора) приведённая масса винт+ротор+гайка добавляет паразитное сопротивление/«провал» нагрузки. Регулятор должен упреждающе (feed-forward по ускорению, `J_eq · a`) компенсировать инерционный момент, чтобы ощущаемая нагрузка оставалась равной заданному весу. Параметры: `inertiaCompensationEnabled`, `equivalentInertiaKgm2` (или приведённая масса в кг на сторону), `inertiaCompensationGain` (0–100 %), ограничение по максимальному компенсирующему моменту. Измерение `J_eq` — сервисная процедура (разгон без нагрузки, анализ тока/ускорения); проверка — «пустой» подход с эталонным грузом на смене направления.
- [x] **Сглаживание смены направления**: в зоне разворота (нижняя/верхняя точка) — плавный переход момента без рывка и «ступеньки» усилия, настраиваемая ширина зоны и профиль (S-кривая); компенсация люфта при реверсе (см. раздел 6).
- [x] **Профили момента по сценариям** (тренировка / калибровка / показ диапазона / сервис / гость) — сейчас профили только описаны, `torque_limit_percent` фиксированный.
- [x] **Плавное нарастание нагрузки** (ramp-in) в начале подхода и сброс момента в конце (ramp-out), настраиваемое время.
- [x] **Ограничение максимальной нагрузки** по `max_load` и `guest_weight_limit` на уровне привода, а не только safety-gate.
- [x] **Кривые нагрузки по диапазону** (`loadCurve`): постоянная; «резина» (растёт к верхней точке); «цепи»; убывающая. Хранить как функцию от `amplitudePercent`, показывать пользователю простыми пресетами.
- [x] **Изокинетический режим** — постоянная скорость независимо от усилия пользователя (нагрузка подстраивается), ограничение по максимальному моменту.
- [x] **Изометрическое удержание под нагрузкой** — упражнения на время в заданной точке диапазона: гриф держит нагрузку, пользователь сопротивляется; контроль дрейфа и таймер.
- [x] **Односторонние упражнения** (одной рукой/ногой): нагрузка только на одной стороне грифа или намеренно асимметричная; исключить ложное срабатывание защиты от перекоса (`asymmetricLoadAllowed` в параметрах упражнения).
- [x] **Смена нагрузки во время подхода** (дроп-сет, отказ, «страховка»): плавное изменение момента, пока пользователь держит гриф; ограничение скорости изменения `loadChangeRateKgPerSec`.
- [x] **Автоматический разминочный вес** — сниженная нагрузка для разминочных сетов из `buildStrengthPlan`, отдельное правило для первого подхода дня.
- [ ] **Режим теста 1ПМ / максимума** с усиленной страховкой и пошаговым набором веса.
- [x] **Исходное усилие датчика**: источник данных об усилии — ток привода или тензодатчик (`forceSource: 'current' | 'load_cell'`), фильтрация шума, калибровка нуля усилия перед подходом.

- [x] **Профиль «показ диапазона»** — реальное медленное движение нижняя → верхняя точка с низким моментом, останов при сопротивлении.

## 5. Калибровка и диапазон

- [x] **Калибровка конечных положений в режиме «невесомого грифа»**: при настройке упражнения приводы переходят в gravity compensation (см. раздел 3) — пользователь свободно руками ставит гриф в нижнюю точку, нажимает «Зафиксировать нижнюю», затем в верхнюю — «Зафиксировать верхнюю»; гриф остаётся там, где его отпустили, без усилия и без кнопок «вверх/вниз». Аналогично задаётся `fixedPositionMm` для `fixed_position`. Требования: вход в режим только через safety-gate и после подтверждения свободной зоны; лёгкое вязкое сопротивление (`calibrationDampingGain`), чтобы гриф не «гулял» от касания; ограничение скорости перемещения рукой (`calibrationMaxSpeedMmPerSec`) и мягкое торможение у системных лимитов; кнопка «Зафиксировать» активна только когда гриф неподвижен N мс; при E-STOP/ошибке/таймауте бездействия — переход в удержание, а не сброс компенсации; после фиксации точек — автоматический показ диапазона (медленное движение нижняя → верхняя) для подтверждения; ручное управление кнопками/шагами ±1/±5 мм остаётся как запасной вариант.
- [x] **Пошаговая калибровка с реальным приводом**: свободное перемещение (`free_move`) с низким моментом, фиксация нижней/верхней точки по кнопке, проверка `upper > lower + minRangeMm`.
- [ ] **Запас к точкам калибровки** (`rangeMarginMm`) — рабочие границы чуть внутри зафиксированных точек.
- [ ] **Стартовая точка и направление первой фазы** в калибровке (см. раздел 1).
- [ ] **Устаревание калибровки** по факту: после homing / сброса нуля / изменения параметров ШВП пометить калибровки как `outdated`, а не только по `expires_at`.
- [ ] **Калибровка по типам** (`bar_range`, `handle_range`, `position_check`) — сейчас один тип.

- [x] **Оценка качества повтора** по траектории (глубина, симметрия фаз, паузы) как основа для будущих подсказок по технике.

## 7.1. Пауза, отдых и переходы между упражнениями

- [x] **Безопасная пауза посреди повтора**: пользователь под нагрузкой → медленно довести в стартовую точку с помощью или перейти в удержание; запрет резкого сброса нагрузки.
- [ ] **Поведение грифа во время отдыха** (`rest-screen`): удержание в стартовой точке с низким моментом / парковка / ожидание захвата — настраивается; отдых не должен требовать движений от пользователя.
- [ ] **Переход к следующему упражнению**: автоматический выход в новую стартовую точку/высоту только после подтверждения свободной зоны; при смене режима (`bar_range` → `fixed_position`) — явный экран смены конфигурации.
- [x] **Возобновление после «Завершить подход»/«Пропустить»**: гриф не должен оставаться под нагрузкой без пользователя — таймаут удержания → мягкая парковка.
- [x] **Возобновление после сбоя UI/бэкенда** (страница перезагружена, WebSocket оборвался): состояние подхода восстанавливается из `hardware_runtime`, приводы в это время держат позицию сами.

## 8. Безопасность на уровне механики

- [x] **Аварийный стоп на уровне привода** (не только программный): удержание позиции с контролем момента, затем блокировка; проверка, что после E-STOP гриф не падает.
- [x] **Контролируемое снятие E-STOP**: восстановление только в удержание, повторный homing/проверка синхронности при необходимости.
- [x] **Watchdog связи с приводами**: потеря пакетов/таймаут → переход в безопасное состояние, настраиваемый `timeoutMs` / `retryCount`.
- [x] **Пределы по току и температуре** приводов с предупреждением и остановкой; телеметрия уже есть (`current_a`, `temperature_c`), но пороги и реакции нет.
- [x] **Обнаружение препятствия** (рост тока без движения) в режимах возврата/показа диапазона/сервиса → немедленная остановка.
- [ ] **Ручное управление только по удержанию** с автостопом при отпускании и таймаутом команды (сейчас `manual_move` — дискретное перемещение на дистанцию).
- [ ] **Блокировка ручного управления** при критическом рассинхроне и отключённом приводе (как в документации).
- [x] **Поведение при пропадании питания**: механический/электромагнитный тормоз на приводах, гриф не опускается; после восстановления — позиция неизвестна → обязательный homing, безопасное отпускание тормоза.
- [ ] **Аварийное ручное опускание грифа** без питания/при отказе приводов (ручной привод, размыкание тормоза) — процедура и инструкция для сервиса.
- [x] **Heartbeat backend → приводы**: если backend упал/зависает, приводы сами переходят в удержание по таймауту, а не продолжают последнюю команду.
- [x] **Последовательность включения** (power-on self-test): проверка связи, тормозов, концевиков, температуры, версии прошивки → homing → «Тренажёр готов». Без успешного POST — блокировка запуска.
- [x] **Абсолютный vs инкрементальный энкодер**: при инкрементальном — позиция теряется при каждом включении, нужен homing; учесть в UI и safety-gate («Позиция не определена»).
- [ ] **Потеря/дрейф энкодера в работе**: сравнение позиции по энкодеру с ожидаемой (по командам/второй стороне), при расхождении — остановка и переопределение.
- [ ] **Физические органы управления**: кнопка E-STOP на корпусе, кнопки старт/стоп на грифе, педаль, «мёртвая рука» для сервисных перемещений — ввод через контроллер, приоритет выше UI.
- [ ] **Тепловой режим удержания**: длительное удержание под нагрузкой (фиксированная позиция, паузы) нагревает двигатели — контроль duty cycle, снижение тока удержания за счёт тормоза, охлаждение.
- [x] **Ограничение скорости изменения момента** и защита от автоколебаний регулятора (резонанс, «дрожание» грифа) — фильтры, настройка ПИД по профилям, автотюнинг в сервисном режиме.
- [ ] **Простой (idle)**: по таймауту `idle_lock_minutes` — парковка, снятие нагрузки, отключение приводов; выход из простоя через homing-проверку.
- [ ] **Датчик зоны движения** (опционально): световой барьер/ИК-датчик под грифом — блокировка автоматических перемещений при наличии препятствия.

## 9. Диагностика и тесты приводов

- [x] **Реальные тесты** вместо заглушек: тест связи (латентность по сторонам), тест чтения позиции, тест синхронности, тест удержания позиции, тест низкомоментного движения, тест аварийной остановки.
- [x] **Журнал ошибок приводов** с кодами (`E-COMM-02` и т.п.), действиями «Повторить связь» / «Сбросить ошибку».
- [x] **Запись телеметрии подхода** (позиция/скорость/ток по сторонам с высокой частотой) для последующего анализа техники и отладки регуляторов.
- [x] **«Чёрный ящик» инцидентов**: кольцевой буфер телеметрии последних N секунд, сохраняемый при E-STOP, ошибке привода, критическом рассинхроне.
- [ ] **Версии прошивок и параметров приводов**: чтение, сравнение с эталонным профилем (`modbus` profiles), предупреждение при расхождении, откат.
- [x] **Счётчики ресурса**: пройденный путь ШВП, число циклов, часы под нагрузкой — для планирования обслуживания.
- [x] **Проверка точности нагрузки** эталонным грузом как регулярный сервисный тест (дрейф `kgToTorqueFactor`).

## 10. Интеграция с реальным протоколом

- [ ] **Драйвер приводов на базе Modbus-слоя** (`modbus_service`): маппинг команд `hardware_runtime` (`start_motion`, `home`, `manual_move`, `hold`, `set_torque`) на регистры, чтение телеметрии в цикле.
- [x] **Абстракция адаптера**: единый интерфейс для эмулятора и реального привода, чтобы safety-gate/realtime не зависели от протокола.
- [x] **Частота цикла управления** — отдельный от realtime-broadcast поток управления (10 мс–20 мс), broadcast с прореживанием.
- [ ] **Параметры связи в настройках** (порт, скорость, адреса сторон, таймаут, повторы) и применение при подключении.
- [ ] **Где живёт контур управления**: критичные по времени вещи (синхронизация сторон, ограничение скорости опускания, страховка) — в контроллере/прошивке приводов, backend задаёт параметры и цели; Python по Modbus не гарантирует миллисекундные реакции.
- [x] **Бюджет задержек**: измерить и зафиксировать цепочку «датчик → контроллер → backend → WebSocket → UI»; UI-индикаторы (повторы, положение) не должны отставать более чем на заданный порог.

## 11. Эмулятор с физикой и тестирование

- [x] **Физическая модель в эмуляторе**: масса грифа, трение, усилие пользователя (сценарии: ровный подход, отказ, рывок, отпустил гриф, перекос), чтобы гонять регуляторы и safety-логику без тренажёра.
- [x] **Сценарии сбоев в эмуляторе**: потеря связи одной стороны, дрейф энкодера, перегрев, E-STOP посреди повтора, пропадание питания.
- [ ] **Hardware-in-the-loop стенд** и чек-лист приёмочных тестов безопасности перед каждым релизом (E-STOP, падение грифа, рассинхрон, перегрузка).
- [x] **Замена клавиатурной симуляции** (`Ctrl+↑/↓`) на управляемую через API «виртуальную руку» с усилием — пригодно для e2e-тестов.

## 12. Данные упражнений и параметры на уровне каталога

- [ ] **Разметка каталога упражнений** машинными параметрами: `machineMode` (`bar_range` / `fixed_position` / `no_machine`), направление усилия (`push` / `pull`), `startPoint`, допустимые `loadMode`, `asymmetricLoadAllowed`, пресет высоты фиксации. Сейчас есть только `equipment` и список исключений `CALIBRATION_EXEMPT_EQUIPMENT`.
- [ ] **Наследование параметров** между похожими упражнениями (варианты одного движения) — чтобы не калибровать каждое отдельно; предложение «использовать калибровку от …».
- [ ] **Калибровка, зависящая от положения тела/скамьи**: пометка, что для упражнения нужна проверка позиции, если менялась скамья/стойка.
- [ ] **Учёт роста и антропометрии профиля** для предзаполнения диапазона и высоты фиксации; пересчёт при изменении профиля.
- [ ] **Разделение настроек**: системные (лимиты, профили движения, ШВП) / пользовательские (усилие удержания, кривая нагрузки, поведение при достижении цели) / на упражнение (калибровка, режим, стартовая точка).

## 13. Страница отладки и настройки механики (инженерный режим)

Отдельный экран в системных настройках (доступ по сервисному PIN, только в сервисном режиме), где все параметры из разделов 1–12 можно смотреть, менять и сразу проверять на живом тренажёре или эмуляторе. Сейчас есть только Modbus-отладка на уровне регистров (`/api/modbus/*`) и вкладка «Приводы и ШВП» с чтением статуса.

### Структура страницы

- [x] **Группы параметров** (вкладки/аккордеоны): компенсации (вес грифа, трение, инерция, люфт); стартовое положение и удержание; синхронизация сторон; режимы и кривые нагрузки, пересчёт кг → момент; профили движения и лимиты; детекция повторов/отказа/захвата; безопасность (пороги тока/температуры, скорость опускания, таймауты); регулятор (ПИД/фильтры по профилям); ШВП и связь.
- [x] **Карточка параметра**: текущее значение, значение по умолчанию, безопасный диапазон (жёсткие границы нельзя превысить даже в инженерном режиме), единицы, краткое описание «на что влияет», кто/когда менял. Слайдер + числовой ввод + шаги ±.
- [x] **Режим применения**: «применить временно» (live, до перезагрузки/выхода из сервисного режима) и «сохранить»; применение к движению без перезапуска контура, с плавным переходом значения, если гриф под нагрузкой.
- [x] **Пресеты и профили настроек**: сохранить/загрузить/сравнить набор параметров («заводские», «мягкие», «тестовый стенд»), экспорт/импорт JSON, diff с текущими; откат к предыдущей версии одной кнопкой. Переиспользовать механизм профилей из `modbus_service`.
- [x] **История изменений** — каждое изменение в audit log (параметр, было → стало, актор, временно/сохранено).

### Live-панель и тестовые сценарии

- [x] **Графики телеметрии в реальном времени** (позиция Л/П, скорость, ускорение, ток/момент Л/П, рассинхрон, оценка усилия пользователя, заданный vs фактический момент, температура) с выбором каналов, паузой, курсором и временным окном; частота выше, чем у обычного realtime-канала (отдельный debug-поток).
- [x] **Маркеры событий на графике**: смена направления, засчитанный повтор, срабатывание страховки, коррекция синхронизации, детекция захвата/отпускания, изменение параметра — чтобы видеть эффект настройки сразу.
- [x] **Тестовые сценарии одной кнопкой**: «невесомый гриф» (проверка дрейфа), «удержание N кг», «разгон/реверс без нагрузки» (оценка инерции и трения), «синхронный ход вверх-вниз», «имитация отказа/рывка» (на эмуляторе), «шаг момента» для оценки отклика регулятора. Все — на низких скоростях, через safety-gate, с подтверждением свободной зоны и всегда видимым СТОП.
- [x] **Мастера измерения** (пошаговые): масса грифа и подвижных частей, трение вверх/вниз, приведённая инерция, люфт, `kgToTorqueFactor` эталонным грузом — с автоматическим предложением значений и кнопкой «принять».
- [x] **Запись и воспроизведение**: сохранить отрезок телеметрии с набором параметров и комментарием, сравнить две записи на одном графике (до/после настройки), открыть запись из «чёрного ящика».
- [x] **Состояние контура управления**: текущий режим приводов, активный профиль, слагаемые момента (вес + компенсация грифа + трение + инерция + коррекция синхронизации), латентность цикла, пропущенные такты, состояние heartbeat.

### Безопасность страницы

- [x] Доступ только в сервисном режиме по PIN; при активной тренировке изменение параметров безопасности блокируется.
- [x] Жёсткие границы (макс. момент, макс. скорость, физические лимиты) зашиты на стороне контроллера и со страницы не меняются.
- [x] Временные значения автоматически откатываются при выходе из сервисного режима, E-STOP или потере связи с UI.
- [x] СТОП и статус приводов всегда видны; любой тестовый сценарий прерывается одним касанием.

### Backend

- [x] **Единый реестр параметров механики** (схема: ключ, тип, единицы, default, min/max, hard-limit, группа, описание, требуется ли перезапуск) — UI строится по реестру, а не хардкодом.
- [x] API: `GET/PUT /api/hardware/tuning` (с `apply: 'temporary' | 'persist'`), `GET /api/hardware/tuning/schema`, `POST /api/hardware/tuning/presets`, `POST /api/hardware/tuning/scenarios/{name}`, WebSocket `/api/hardware/telemetry-debug` с повышенной частотой; все записи — в audit log.

## Предлагаемая приоритизация

1. Безопасная база: POST, homing, тормоз/пропадание питания, heartbeat, ограничение скорости опускания, E-STOP на приводе.
2. Лимиты/профили из настроек + абстракция адаптера + эмулятор с физикой (фундамент для всего остального).
3. Реестр параметров + страница отладки с live-графиками и мастерами измерения — без неё невозможно настраивать всё остальное на железе.
4. Компенсации (вес грифа / «невесомый гриф», трение, инерция) и калибровка конечных положений в этом режиме.
5. Разметка каталога упражнений машинными параметрами (`machineMode`, `startPoint`, направление усилия).
6. Стартовое положение с настраиваемым усилием удержания; режим фиксированной позиции.
7. Активная синхронизация сторон и `desync_action`.
8. Режимы нагрузки, пересчёт кг → момент, страховка при отказе.
9. Детекция повторов/темпа/застревания по реальному движению; пауза/отдых/переходы.
10. Кривые нагрузки, изокинетика, изометрия, 1ПМ.
11. Обслуживание, тесты приводов, чёрный ящик, счётчики ресурса.
