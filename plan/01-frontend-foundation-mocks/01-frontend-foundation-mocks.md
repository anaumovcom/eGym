# Этап 1 — Frontend foundation + mocks

## Цель

Создать основу полноценного React-фронтенда Forma на моках: проект, дизайн-систему, маршрутизацию, layout, системные компоненты, моковый API и первые базовые экраны.

После этапа должен быть рабочий frontend shell, в котором можно выбрать пользователя, увидеть главную страницу, проверить верхнюю панель, левое меню, аварийный `СТОП`, модальные поверхности и моковые системные статусы.

## Frontend setup

1. Создать frontend-приложение на React + Vite + TypeScript.
2. Подключить TailwindCSS.
3. Подключить shadcn/ui + Radix UI.
4. Подключить `lucide-react`, `@phosphor-icons/react`, при необходимости `react-icons`.
5. Подключить React Router.
6. Подключить TanStack Query.
7. Подключить Zustand.
8. Подключить MSW для мокового API.
9. Подключить Vitest, Testing Library, Playwright.
10. Подключить Storybook для компонентов и состояний.

---

## Архитектура frontend

Рекомендуемая структура:

```text
frontend/
  src/
    app/
    routes/
    shared/
      ui/
      icons/
      api/
      config/
      lib/
    entities/
      user/
      machine/
      exercise/
      workout/
      muscle/
    features/
    screens/
    mocks/
```

Архитектуру держать модульной: экраны не должны напрямую дублировать общие компоненты.

## Дизайн-система

Реализовать базовые токены:

* тёмный фон;
* золотой основной акцент;
* красный аварийный цвет;
* зелёный/жёлтый/оранжевый/красный/бордовый для готовности, усталости и ошибок;
* типографика под 4K-экран;
* крупные touch-targets;
* карточки, панели, вкладки, модалки, бейджи, кнопки;
* состояния hover/focus/active/disabled/loading.

## Моковый API

Создать моковые данные для:

* пользователей;
* выбранного пользователя;
* статуса тренажёра;
* левого и правого приводов;
* безопасности;
* сегодняшней рекомендации;
* текущей усталости мышц;
* краткого прогресса;
* уведомлений и блокировок.

MSW должен отдавать данные по маршрутам, похожим на будущий backend API, чтобы затем заменить моки без переписывания экранов.

---

## Экран выбора пользователя

Реализовать полный экран:

* карточки пользователей;
* гостевой режим;
* добавление пользователя как недоступное или отдельное действие по документации;
* системный статус тренажёра;
* аварийный `СТОП`;
* переход на главную после выбора;
* состояния готовности, предупреждения и блокировки.

---

## Главная страница

Реализовать полный экран:

* главную рекомендацию;
* кнопку основного действия;
* карточку сегодняшней тренировки;
* статус тренажёра;
* краткую карту усталости;
* блок рекомендаций;
* быстрый старт;
* краткий прогресс;
* состояния: тренировка есть, тренировки нет, высокая усталость, тренажёр не готов, ошибка привода, аварийная остановка.

## Acceptance criteria

* Приложение запускается локально.
* Все базовые компоненты доступны в Storybook.
* Выбор пользователя ведёт на главную.
* Верхняя панель и левое меню соответствуют общим документам.
* `СТОП` работает поверх модалок и открывает аварийный оверлей.
* Главная страница отображает все состояния на моках.
* Нет отдельного экрана предстартовой проверки.
