# V2: реальная сложность исходных 120 линий

Версия правил — **achievements-rules-1.3.0**. Коллекция: **152 линии / 515 ступеней**:
исходные 120 / 387 и добавленные 17 exercise + 15 muscle / 128.

## Два обязательных условия, а не награда за первый старт

Для выдачи нужны **одновременно** историческая числовая веха и соответствующее
число разных дней подтверждённой практики. Первая запись/подход/тренировка,
разминка, одни заметки или одно сохранение награды не дают. Дни не обязаны быть
подряд, увеличивать вес/интенсивность ради награды не требуется.

Исторические milestone-пороги и ID намеренно сохранены: оплаченные фразы честно
говорят о достигнутой вехе и не становятся поводом повторно покупать 503 комплекта.
Новая сложность — отдельный обязательный критерий, не косметическая задержка:
нужны 2 полных рабочих подхода или 60 фактических секунд за квалифицирующий день.
Вехи, все требования по дням и фактический зачёт публикуются в каталоге/API/UI.

| Группа | Минимум дней для последовательных ступеней |
|---|---|
| Начало пути | 12 / 24 / 48 |
| Регулярность | 12 / 32 / 72 / 144 / 240 / 400 |
| Практика | 16 / 40 / 90 / 160 / 260 / 420 |
| Движение / репертуар | 12 / 30 / 75 / 150 / 240 |
| Вес и объём | 16 / 40 / 90 / 160 / 260 |
| План | 12 / 30 / 75 / 150 / 240 |
| Сопоставимый прогресс | 12 / 24 / 48 дней с подтверждёнными улучшениями |
| Наблюдения / истории | 12 / 30 / 75 / 150 / 240 |
| Большие главы | 12 / 30 / 75 |
| Датчиковые данные | 12 / 30 / 75 / 150 / 240 |
| Каждое упражнение / мышечная группа | 12 / 30 / 75 / 150 |

Профили обрезаются по фактической длине линии. Исключения по достижимости:
`rhythm.after_return` — **12 / 20 / 30** дней внутри 42-дневного окна после
возвращения (75 дней в таком окне невозможно); `chapter.30_days` — **12 / 18 / 24**.
Дни до возвращения не удовлетворяют критерию после возвращения.

## Проверка подсчёта

- Для старых счётчиков исключены незавершённые тренировки и записи без finished_at,
  unknown/skipped completion и все явные simulation/test/emulator/synthetic маркеры.
- Наличие reps/duration не может увеличить actual_value; секунды не становятся reps.
- Знакомое упражнение требует **трёх предыдущих разных дней**. Второй подход третьего
  дня не превращает этот же день в четвёртый.
- Произвольный builder workout не считается завершённой сохранённой программой:
  нужен programId в исходном плане и его подтверждённое выполнение.
- Для дневника, плана, историй, типа движения, веса и датчиков дни доказательства
  пересекаются с реальными квалифицирующими днями, а не берётся минимум двух
  независимых lifetime-сумм. Содержание заметок не оценивается и не передаётся ИИ.
- Scoped-анатомия использует канонические explicit primary или проверенную статическую
  карту упражнений; порядок русских legacy labels не является анатомическим фактом.
- Новые gated grants версии 1.2 не превращаются в grandfathered после смены версии.
  Старые негейтированные исторические grants сохраняют прежнюю совместимость.

## Сохранность оплаченного

Согласование архивирует исходный JSON по SHA256 до изменения, обновляет метаданные
правил и аддитивно добавляет линии. Поля title/phrase/imagePrompt/fishMarkup/audioText,
contentOrigin/editorialStyle оплаченных совпадающих tier ID сохраняются дословно.
Media manifest и файлы при перебалансировке не сбрасываются. Content version не меняется.
Ledger общий для всех версий, historical holds и sent/unsettled liabilities не обнуляются.

Windows persistence: уникальный временный файл, flush/fsync, atomic replace с ограниченными
локальными повторами PermissionError, job-wide lock. При постоянной блокировке fsynced temp
остаётся доказательством для восстановления. WAV/image bytes и receipts сохраняются до
settlement; неизвестный исход запроса никогда не разрешает автоматическую повторную оплату.

## Границы проверки

Тесты работают на временных fixture-БД. Реальная пользовательская БД, backfill, миграции
и оборудование не запускались. Для browser QA предусмотрен отдельный frontend-only
Playwright config; все API/WebSocket запросы перехватываются fixtures.
Неполная платная коллекция должна оставаться complete=false до разрешения блокировок.
