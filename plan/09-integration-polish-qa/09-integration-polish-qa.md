# Этап 9 — Интеграция, полировка и QA

## Цель

Собрать все части в единую полноценную систему, заменить моки реальными API, проверить UX, производительность, безопасность, стабильность и полные пользовательские сценарии.

---

## Основные источники из документации

* все документы `docs/**/*.md`;
* все README предыдущих этапов;
* фактические OpenAPI-контракты backend;
* сценарии frontend на моках.

---

## Интеграция frontend и backend

Сделать:

* переключение frontend с MSW на real API;
* сверку DTO;
* обработку реальных ошибок;
* загрузочные состояния;
* optimistic updates только там, где безопасно;
* повтор запросов для некритичных операций;
* блокирующие ошибки для safety-сценариев;
* корректное восстановление состояния после перезагрузки.

---

## Сквозные сценарии

Проверить полностью:

* выбор пользователя → главная;
* быстрый старт → настройка → выполнение → отдых → итог упражнения;
* сегодняшняя тренировка → все упражнения → итог тренировки;
* календарь → назначение → запуск тренировки;
* программа → адаптация → календарь → запуск;
* каталог → карточка упражнения → старт;
* профиль → фото прогресса;
* прогресс → детализация;
* усталость → выбор мышцы → рекомендации;
* системные настройки → диагностика → блокировка / разблокировка;
* аварийный `СТОП` из каждого live-состояния.

---

## UX-полировка

Проверить:

* 4K layout;
* сенсорные размеры кнопок;
* читаемость с расстояния;
* поведение модалок;
* правые панели;
* пустые состояния;
* ошибки;
* плавность переходов;
* отсутствие лишних экранов;
* единые термины;
* единые цвета усталости и безопасности.

---

## Тестирование

Добавить и стабилизировать:

* unit-тесты критической логики;
* component-тесты;
* API integration-тесты;
* E2E-тесты Playwright;
* hardware emulator-тесты;
* тесты восстановления после выключенного сервера;
* тесты аварийной остановки;
* тесты миграций;
* тесты загрузки фото;
* тесты рекомендаций.

---

## Производительность

Проверить:

* скорость загрузки dashboard;
* скорость каталога упражнений;
* фильтры и поиск;
* графики прогресса;
* live-экран выполнения;
* задержку realtime-статусов;
* нагрузку на backend;
* размер frontend bundle;
* работу на целевом устройстве.

---

## Acceptance criteria

* Все основные сценарии проходят на real API.
* Моки можно отключить без потери функциональности.
* Нет расхождений между документацией, frontend и backend по ключевым сценариям.
* `СТОП` и safety-блокировки проходят ручные и автоматические проверки.
* Усталость мышц корректно пересчитывается после паузы или выключения сервера.
* UI готов к демонстрации на целевом 4K-экране.
* Все критические автотесты проходят стабильно.
